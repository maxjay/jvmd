Stage 3 attributes one source file at a time against stubs, writes its class files as content-addressed results, and writes a proof of exactly which identities the result depends on, verified by the same descent of sums that stages 1 and 2 built. Greenfield: nothing under `jvmd-lsp`, `jvmd-analyzer` or the old `jvmd-index` is reference or guidance.

## 1. Vision

Stages 1 and 2 built Java's missing interface files: every declaration of every jar, JDK module and source module as a fact with a resolution identity `h`, leaves `T`, `N`, `E`, `O` with sums, `k` per leaf, routes bound at read time, definer indexes, stubs javac can compile against, and a per-file header proof. Nothing in them has looked inside a method body. Stage 3 does, and it is the stage where the compiler claim is either earned or not.

**What stage 3 adds.** One job, `Attribute(f)`: one compilation unit, attributed and generated by javac against stubs of everything else on its route and of its own module's leaf. Its output is `f`'s class files as content-addressed results, its diagnostics, and a proof of exactly which identities its result depends on, structured as the sums already are: a header of the route's and the own leaf's projected identities, then per type `oSum`, then per named range the sum of T (form 0) or N (form 1); only T ranges use the per-type oSum gate. A driver that runs `Attribute` over every file of a project in dependency order. A reverse index from each member range to the files whose bodies resolved through it, which is find-references at member level. An output tree per module scope, synced to a directory by `Diff`, so `java -cp` runs the project with no build tool involved.

**The A layer.** T holds only the resolution projection `res`, with `h = Digest(m || res)` and `k = root(T).hash`. Retained annotation and parameter metadata live in A with annotation-type edges in EA, addressed by `a = Digest(A.hash || EA.hash)`. The minimal warning states javac reads from Deprecated and SafeVarargs belong in res; their full retained annotations also remain in A. In particular, changing only Deprecated.since changes A/a and leaves T/k/r and stub bytes unchanged. These projections may overlap. Equal APIs give equal k; metadata can differ independently. This LAYOUT 4 foundation amends stages 1 and 2 before Stage 3 codecs.

**What a body depends on.** Everything javac reads from another type while attributing and generating `f` is one of three things: the header of every type in the supertype closure of every type javac tested or inferred (not only the types `f` names: the attributed type of every expression, since applicability, conversion and inference walk those closures); the set of members named `n` of kind `kind` in a type `t`, over every type the lookup walked (overload resolution and hiding are over sets, a constant's value is in its member's `res`, a functional interface is its abstract method set, a subclass depends on the whole method set of its supertypes for override, abstract and bridge checks); or the absence of a type where a simple name could have resolved first (the file's own package, an inherited member type, another on-demand package). All three are the same thing: an expected range identity in a tree that already exists. A member set is a range sum of the definer's `T` over the prefix `(t, kind, name)`; a type header is the degenerate range of one entry; an expected-empty group is the same range with sum zero; an absent type is a range of the definer indexes with sum zero. One proof scheme over three trees (`T`, `N`, `D`), where the stage 2 sketch had six kinds. Every identity is a sum, compared and never used as a key; nothing in a proof names `k`.

The `ContentTree` that carries all of this is a prolly tree: sorted entries, content-defined chunk boundaries (`hash64(key)` against `B`, capped by `CAP`), interior levels chunked the same way, so the shape is a function of the entry set and a local edit rewrites O(depth) nodes. The Merkle hash on each node gives exact structural identity and sharing; the sum on each node gives the projected semantic identity of its range. Stage 3 uses both as they were built: hashes to find where content moved (`Diff`, `apply`), sums to decide whether a projection changed (every proof identity). Without the content-defined boundaries the hashes would say "changed" far beyond the semantic delta; without the sums the hashes would say only that something changed.

**What it does not do.** It does not decide when to rerun anything: that is the LIVE loop, which consumes these proofs and is its own document. It does not speak LSP. It does not restore state at startup (warm boot). It does not run the build tool, produce the project model, or regenerate generated sources. It does not run javac over a module as a unit, ever.

**Where this leaves the claim.** After stage 3, for one project on one machine: edit a body in libAB, exactly one class file is regenerated, and `oSum` unchanged tells LIVE at once that no header moved (whether the JVM can also HotSwap it is a member-schema question LIVE answers from the class file). Add a method to libAB's `K`: nothing in A is recompiled except bodies that resolve a name through that range and types that extend `K` (whose override, abstract-method and bridge checks read `K`'s whole method set, so re-attributing them is correct, not conservative). Bump an internal library whose API did not change, no proof fails anywhere. Each of those is an invariant in section 7 with a test, and the oracle for all of them is javac over the same inputs, never a build tool's output directory.

### 2.2 The attribution unit

### 2.2.1 Module descriptors: zero-body derivation

`module-info.java` never enters `Attribute`. Stage 2's canonical `Res.Module` fact at `T[module-info]` supplies descriptor/resolution state, including implicit java.base, module/version, required-module versions, exports, opens, uses/provides with resolved binary names, the referenced InnerClasses entries needed by the descriptor output, and the minimal warning projection. The exact keyed `A[module-info]` entry supplies complete retained annotation metadata, including full warning annotations. These two entries are the semantic portion of the derivation; EA is not an output-byte input. Source and binary extraction must independently produce equal T, A and EA for module-info before emission relies on them.

Stage 3 deterministically emits `module-info.class` from those entries and a tiny `moduleEmitFormat`, stores the bytes under ordinary `CF|Digest(bytes)`, and includes the class in the scope's OUT tree. The derivation key is `Digest(str "module-info derivation v2" || hT(module-info) || opt<hA(module-info)> || moduleEmitFormat)`, domain-separated from source ACI. `moduleEmitFormat = u16 emitterVersion(2) || u16 majorVersion || u8 sourceFile`. It contains only fixed/compiler inputs that affect the output bytes. The declared descriptor target/release determines majorVersion; the last `-g` setting determines SourceFile emission. Stage 2 already records required-module versions from that declared release's module view. No k, a, R, RA, module sum, body-proof shortcut or reverse-index lookup enters this derivation. Successful descriptors persist/reuse RS/CF directly and have no C, U or body-X record. The update rule inspects Diff of T/A and schedules the descriptor only if the module-info key itself changed (or emission format changed); it does not query X. Source whitespace and executable-body edits are not descriptor inputs.

Unchanged descriptor and emission options mean no descriptor emission work. One directive edit changes only the module-info derivation among outputs that otherwise consume unchanged inputs. An independent javac oracle must compare the emitted descriptor byte for byte for supported descriptors. Exact validation of directives, where not already supplied by Stage 2, belongs to Stage 2/header/module-resolution proofs. The deferred module-path boundary applies only to compilation of ordinary Java under JPMS readability/export semantics; it does not defer module-info.class. Native coverage includes implicit/explicit required modules, required versions, module versions, qualified exports/opens, uses/provides, open modules, debug options and declared Java 21/25 descriptor releases. It also includes explicit/on-demand imports of nested services, multiple enclosing levels, native InnerClasses order, and descriptor reuse after an unrelated method edit. A provider flag change alters the descriptor metadata and therefore its keyed fact, even if the directive text is unchanged. Annotation coverage must include CLASS/RUNTIME retention, SOURCE exclusion, repeatable/nested annotations, enum/class/array values, all primitive encodings, modified UTF-8, and the warning/full-annotation split. A retained annotation-value edit can change only A while still changing descriptor bytes; an unrelated T/A edit must leave the descriptor result unchanged. Complete Stage 2 directive diagnostics remain completion work; a zero-body emitter is not evidence that header validation is complete.

Parser 6 extends the canonical Res.Module codec with `list<str binaryName || opt<str> outerBinaryName || opt<str> innerName || u16 flags>`, preserving the native InnerClasses traversal order. Source service names are resolved in the descriptor's native import/header environment under the current classpath policy; no method body is attributed. The source producer records exact T/header and absent-name observations, including each enclosing declaration whose metadata is emitted. The binary producer reads the descriptor's actual InnerClasses entries through the same codec. Stage 3 still consumes only the resulting module-info fact. Earlier MACHINE parser generations remain separate cold inputs, and LOCAL/BROOT compatibility follows the full MACHINE format. This projection extension does not add JPMS readability validation or claim that invalid-descriptor diagnostics are complete.

Stage 2 persists native descriptor diagnostics separately as `HD|project|module|scope|path`, using the existing diagnostic codec and canonical source display policy. HD is rooted in LOCAL and contains no class output. Stage 3 publishes valid descriptor warnings in scope presentation without putting diagnostic positions, source bytes or unrelated headers into the successful descriptor derivation. A native descriptor header error produces a failed, no-class result, domain-separated by `"module-info header error v1"`, whose identity covers the source bytes, basename, header options and exact observed T/N/D header ranges. Healthy files still publish normally. Parse errors and missing/inaccessible service types are checked against fresh native javac; adding a missing type or making a service accessible invalidates the failed proof. LOCAL 14 fences the new rooted record and repaired candidate-proof semantics. LOCAL 16 corrects source-module annotations and their nested metadata; adding a default to a required annotation member invalidates the failed descriptor's exact method-contract proof. This error path never calls Attribute and does not replace the successful keyed T/A derivation with a wider proof. LOCAL 18 adds javac's native module-declaration lint pass over the already completed detached module symbol. This covers module-name diagnostics, deprecation-annotation consistency and annotation-based suppression without executing bodies or resolving a module graph. These diagnostics remain in HD/scope presentation; a SOURCE-only suppression edit must preserve the successful descriptor identity and emit no new class file. Full directive validation, including module resolution and provider constraints, remains required.

### 2.3 The proof entry, and the resolution universe

| Tree | Key | Expected identity | Meaning |
| --- | --- | --- | --- |
| `T` of the definer (own leaf first, then the route) | `zstr t \|\| u8 kind \|\| zstr name` | range sum of `T` over the prefix | The members named `name` of `kind` in `t`, as a set. `name` empty: every member of that kind. `kind = 0`, `name` empty: the type fact itself, one entry, sum = its `h`. Sum zero: the group is expected empty (a name that would have shadowed, had it existed). |
| `N` of the definer (the by-name tree, A.1) | prefix `zstr name \|\| u8 TYPE \|\| zstr t`: the member types named `name` directly enclosed by `t`, by the simple name and outer javac reads from `InnerClasses`. Never a prefix of a binary name: `$` is legal inside an identifier, so `Base$Foo$Bar` is `Base.Foo.Bar` or a direct member named `Foo$Bar`, and bytes cannot tell them apart | range sum of `N` over the prefix | The member types of `t` named `name`, as Java sees them. Used for inherited member type shadowing, expected empty. `sum(N) = r`, so the same conservation holds. |
| own `O` and route `D` (the three definer indexes) | `zstr typeKey` | both range sums over the key zero | No leaf in the body's universe declares the type. The indexes and `O` are keyed by `typeKey` with `h = Digest(typeKey \|\| oSum)` and `oSum` respectively, so a range over one key sums to zero exactly when the type is absent. |
| processor context | none; per file, in the header and in `ACI` | `processorPathHash`, `optionsHash`, `configProof(f)`: per directory on the configuration chain, `Digest(path \|\| κ)` or zero, read against `RES\|projectKey` | What an isolating processor reads outside the attributed tree (3.5). Present only in a module with a processor path. Resolution reads present in the rewritten tree use ordinary entries; additional processor model reads require their own proof (3.5). |

Positive existence is not a `D` entry: a type the body resolved through is covered by its `T` ranges, read from whichever leaf defines it at verification time.

**The resolution universe of a body is the route plus the module's own leaf.** `f` is compiled against the route's jars and sibling stubs and against the stubs of its own module, and most of what a body resolves through is in its own module. The route's definer indexes do not contain the own leaf (stage 2 keeps a module out of its own route), so stage 3 resolves own-first: `BodyResolver(t)` is the own leaf if its `O` has `t`, otherwise the route's resolver. The own leaf's projected identity is its `r` (`ownR`, the sum of every own `oSum`); it joins the proof header beside the route identities, and an absence is "the own `O` range for `t` is zero and the route's `D` range for `t` is zero". A change to `A.foo()` in the same module as `B` moves `ownR` and fails `B`'s proof with no route identity moving; a new type in the own package shadows an on-demand import the same way. The first drafts had neither and would have validated both.

A proof is a header of the identities it was read against, then its entries grouped by type. The header is `routeHash`, the root sums of `DD|`, `DS|` and `DC|`, and `ownR`, the own leaf's `r`; in a module with a processor path it also carries the processor context (2.3, 3.5). Each definer index entry has `h = Digest(typeKey || oSum)` (stage 2, B.4), so an index's root sum is unchanged exactly when every type it covers still resolves to the same `res`; `ownR` is Σ `oSum` over the own types, so it is unchanged exactly when every own type's `res` is. That gives verification its order: the processor context, when present, must be equal and any additional processor model reads must be verified before applying resolution-only shortcuts (an annotation-only read can change while the context, `k` and `routeHash` stay equal); then equal `routeHash` and `ownR`, valid; equal index sums and `ownR`, valid, since no type in the universe resolves differently; otherwise per type in the proof, an own-first definer lookup, an `oSum` comparison gating only its form-0 T ranges, plus independent comparisons of every form-1 N range; absences as own-`O`-and-route-`D` ranges expected zero. There is no leaf level: the index sums and `ownR` answer the leaf question exactly, and `R` is not needed for `res`-level validity at all.

## 3. Reasoning

Each choice below names what it depends on and what it costs, so a worker who finds a better choice can check it against the same constraints.

### 3.1 One file against stubs, never a module

The result and the proof are per file, so the unit of work is a file: an edit costs one file's attribution and nothing is attributed because it shares a module with the edit. javac can attribute one unit alone only if every declaration it names is available as a class file; stubs are exactly that (stage 2, 3.14 and invariant 14), including for the file's own module, whose leaf stands in for the other files. Every own-module stub is on the classpath, first, `f`'s own types included: first because in a real build the module's sources shadow a same-named classpath type by being source, and the stubs must shadow the same way for the types `f` does not declare; `f`'s own included because javac uses an explicitly given source over a classpath class of the same name (this is how every incremental build with the output directory on the classpath works), so no per-file exclusion is needed and the classpath is constant per route state, which is what lets the task pool exist. Cost: a classpath open per route state, not per file.

What this gives up: javac's cross-file checks within one task (duplicate class detection, `@Override` against a sibling being edited at the same moment). The first is stage 2's duplicate fault already; the second is correct against the stubs, which are the sibling's last committed state, and LIVE decides when they are stale.

### 3.2 Two proof kinds, derived from what javac reads

Attribution of a body reads, from types outside `f`: the header of every type in a supertype closure javac walked (subtyping tests for assignment, cast, catch, applicability and exhaustiveness walk the whole chain, and a change two levels up changes no byte of the referenced type's own fact; flags decide `invokeinterface` against `invokevirtual`, `final`, `sealed` and `permits`; type parameters feed inference); the members named `n` of kind `kind` in a type `t` as a set, for every `t` the lookup walked (overload resolution ranges over every candidate in the closure and over the closures of enclosing classes for an unqualified call, so adding a more specific overload anywhere in them changes the choice; field and method hiding depend on what each type on the lookup path declares; a constant's folded value is its member's `ConstantValue`, in `res`; a functional interface is the set of its abstract methods; a constructor call is the `<init>` group); the whole method set of every supertype of a type `f` declares (unimplemented abstract methods, override and default-method clash checks, and bridge method generation, which is bytes in `f`'s class files); and the absence of a type wherever a simple name could have resolved earlier in javac's order (a member type of an enclosing class or of anything in its closure, a type in the file's own package, a type in another on-demand package or `java.lang`), since any of those appearing would shadow or make ambiguous what the name resolved to.

The type header is one fact, `m = typeKey || 0`. A member set is a contiguous key range of `T`, because `m = zstr owner || u8 kind || zstr name || zstr descriptor` sorts by owner, then kind, then name. Both are therefore the same thing: the range sum of the definer's `T` over a key prefix, read in O(log) off the node sums. One range kind, G, with form 0 for T and form 1 for the exact N member-type prefix. The absent-type kind is D: an own-O and route-D lookup that returns nothing. The six kinds sketched in stage 2's B.5 were these two with the ranges spelled out separately; 1 (member), 2 (overload group), 3 (type) and 4 (package) are G at different prefix lengths, 5 is D, and 6 (definer) is not an entry at all: verification resolves `t` through `DS|`, `DD|`, `DC|` and reads the current definer's T or N according to the entry form, so a definer swap to an API-identical leaf changes no range sum, which is what we want from it.

For every resolution the collector records entries for every type in the closure the lookup walked, not only the type that answered. A field `x` found in `Base` through `Sub` records `(Sub, FIELD, x)` with sum zero and `(Base, FIELD, x)`, so a later `x` declared in `Sub` fails the proof. A method `foo` records `(t, METHOD, foo)` for every `t` in the receiver's closure, plus `(t, 0, )` for each, because the closure itself depends on each type's header. A type `f` declares records `(s, METHOD, )` and `(s, 0, )` for every `s` in its closure. A simple type name `X` resolved through an on-demand import records `D` ranges `p/X` for the file's own package and every other on-demand package, and `N` ranges `(X, TYPE, s)` with sum zero for every `s` in the closure of every enclosing class: the member types named `X` directly enclosed by `s` (2.3). The head identifier of a qualified name that javac classified as a package (`java` in `java.util.List`) records the same absences with no answered package excluded, because a type of that simple name anywhere in scope would reclassify it (JLS 6.5.2).

And, the rule that makes the proof complete rather than name-complete: every type javac attributed an expression to, named in the source or not, records `(t, 0, )` for its whole closure. `f(get())` with overloads `f(Object)` and `f(I)`, where `get()` returns `A implements I`: `A` appears in `f`'s source only as the type of an expression, and removing `implements I` changes which `f` applies while leaving every named signature intact. javac's decisions are functions of attributed types (applicability, conversion, inference, conditional and assignment contexts, thrown types, method reference adaptation), so the collector records the closure of `tree.type` on every expression node. It is a superset of the type-reference rule and deduplicates per file to the same few closures. All of it together: a file's proof is the distinct `(tree, key)` it touched, typically tens to a few hundred, measured in 7.2.

### 3.3 Proofs are sums, verified by descent

The identities compose through the projections already materialised. Once the processor context agrees, equal routeHash and ownR validate the proof. Otherwise, equal root sums of DD|, DS| and DC| together with equal ownR validate it: the complete own-first type-to-res map is unchanged, hence both T and its deterministic N rekey are unchanged. If these global shortcuts fail, resolve each referenced owner, use its oSum comparison to gate only form-0 T ranges, and compare every form-1 N range independently. Adding Base.Foo changes N(Base,Foo) while oSum(Base) stays unchanged because the new type fact belongs to Base$Foo. Absent types are checked against both own O and route D. Each range read costs O(log); no leaf-wide N gate or new nSum is needed.

The sums bind keys. `h = Digest(m || res)`, not `Digest(res)`: a sum over values alone is the same under any assignment of those values to keys, so with `Digest(res)` two constants `x = 1` and `y = 2` of one type could exchange values and leave the range sums of `(t, FIELD, x)` and `(t, FIELD, y)`, `oSum` and `r` all unchanged while every reader's inlined value changed. (A return-type exchange is not an example: the descriptor is in the key, so the keys move too.) With the key inside the digest each entry's `h` is the hash of the pair, and a range sum is the identity of the key-to-value map over that range, which is exactly what a proof entry claims. The definer indexes (`Digest(typeKey || oSum)`) and stubs (`Digest(typeKey || oSum || sorted members)`) already had this shape; `T` and `A` get it in appendix A, and `RES|` and `PD|` (`Digest(path || κ)`, `Digest(elementKey || processorElementProjection(e))`) in 3.5 follow the same rule. The test is invariant 25.

Two things this replaces from the first draft. A per-leaf `r` level: redundant, because the index sums are strictly stronger (a type changing hands to an earlier leaf changes `DC|`'s sum while the old leaf's `r` does not), and dangerous, because a leaf skip could skip `A` groups. And `R` in the header: a reordered route either changes a winner, which `DC|`'s sum shows, or changes nothing that resolution sees. Root *hashes* of the indexes, which the draft compared, move whenever any `k` moves and would have thrown away the shortcut on every unrelated API edit; the sums are the projection, the hashes are the content, and this question is about the projection.

The identities are sums over `h`, which is over `res`, and `res` is by definition what javac reads from a class file, so a proof over `T` is exact for class bytes and for diagnostics both. Nothing javac reads is in `A`.

### 3.4 The A layer: why `tail` leaves `T`

With tail inside T, metadata edits move every storage identity above T even when resolution facts are unchanged. A carries the retained metadata separately. The warning projection in res is minimal: Deprecated attribute/annotation state, forRemoval, and SafeVarargs presence. Full retained warning annotations also stay in A, preserving since and other encoded values. A since-only edit moves a, not k; a warning-state edit can move both.

L remains a function of k. AL|a recovers the full A/EA roots, while `(k,a)` travels in P, Built and persisted SL bindings. Resolution leaf sets, route hashes and DD/DS/DC do not consume a. Header proofs use exact T/N/D observations, including the annotation type and method contract they actually checked; E/EA targets alone are not the whole lookup proof. No RA or nSum is introduced. Processor source-model proofs remain separate from A.

### 3.5 Processors

Annotation processors run inside javac. The model carries each module's processor path, processor options and configuration files (`lombok.config` and the like). Header compilation (stage 2) runs every processor of the module; `Attribute(f)` runs the module's isolating processors over `f`, the only unit in the task. Facts are what javac saw after processing, Lombok's injected members included, and stubs carry them. The rule for processors is the rule for everything else in this document: record what the processor read, at the grain it read it, never a containing scope. A processor whose reads cannot be recorded is unsupported for reuse and is named as such; no module-, route- or project-wide identity stands in for the reads.

**What a processor reads, by class.** The contract is the one processors already declare for Gradle's incremental compilation, `META-INF/gradle/incremental.annotation.processors` in the processor jar: `isolating` (the output for an element depends on that element and on what is reachable from it through javac's `Elements` and `Types`; a generated file names exactly one originating element) or `aggregating` (the output depends on every element carrying one of the processor's supported annotations). Lombok, AutoValue, Immutables, MapStruct and Dagger declare. jvmd subdivides isolating by observed behaviour, recorded per processor class under its `processorPathHash` and established on the fixtures, never inferred from one run: an overlay processor creates no file through `Filer` and edits the AST of the unit in hand (Lombok); an isolating generator creates files through `Filer`, each with one originating element. A processor is executable code, so its identity is `processorPathHash = Digest(ordered bh)` from `P|`, never its `k`: an API-identical jar with changed bodies is a different processor, and `processorPathHash` is an input of stage 2's header compile as well as of stage 3 (appendix F).

**The reads and their identities.** Tested overlay processors rewrite the unit that javac later attributes. Declarations and expressions retained in that rewritten tree are covered by the normal collector. This does not prove arbitrary processor reads that leave no corresponding expression or declaration: those require their own observed proof, or the processor is unsupported for reuse. The processor code uses `processorPathHash`, its effective options use `optionsHash`, and supported configuration lookup uses `configProof(f)`. For Lombok, that proof follows `lombok.config` from the source directory through its parents to the root or `config.stopBubbling`, with `Digest(path || κ)` for a present file and zero for an absent file, against `RES|projectKey`. Unmodelled imports are unsupported.

An isolating generator has one derivation per originating source file, including an empty output set. Its identity is `Digest(processorClass || processorPathHash || optionsHash || path_f || κ_f || configProof(f) || sorted header observations || modelProof_p(f))`. Header observations retain their T/N/D namespace and exact key/range; modelProof records the processor's actual public model queries and answers, including SOURCE annotations, doc comments and declarations absent from either source header. A query is not proved merely because an `Elements` or `Types` call occurred. Fresh isolated processor state must reproduce that origin's native output paths and bytes from captured model answers; shared state must not silently assign the first origin's reads to later origins. Missing or ambiguous answers, exhausted captured allocation sequences and output mismatches are unsupported for reuse. `κ_f` remains an intentional input, so a body edit in f changes this isolating GEN identity.

An aggregating processor consumes a `PD|projectKey|module|scope|processorClass` tree. Each entry is `key = elementKey`, `value = processorElementProjection(e)`, `h = Digest(elementKey || processorElementProjection(e))`. This is a first-class canonical Element-model projection, materialised during the header compile. It includes source path, declaration kind/name/modifiers, explicit and defaulted annotations including SOURCE retention and type-use annotations, type parameters and bounds, superclass/interfaces/permits, members and their declaration order, descriptors/signatures/throws/default values/constants, parameter names, nesting, and doc comments. It excludes executable and initializer bodies, expression trees, and local declarations inside bodies. It is neither the binary A projection nor oSum nor a printed AST skeleton. Queries outside the domain also require their own actual model proof; rootSum(PD) alone does not prove those reads. The aggregate id is `Digest(processorClass || processorPathHash || optionsHash || rootSum(PD) || modelProof_p)`.

For both classes, `GEN|id` holds an exact generated-output ContentTree root, not source bytes. Its keys are output-kind/path pairs and its values are content ids; `GS|contentId` holds generated source bytes. Multiple generated rows may reference the same derivation. Merkle hashes identify exact output sets; Diff identifies changed paths. The manifest's natural sum is not an extra GEN proof or key. Equal derivation inputs must produce the same root hash, otherwise reuse is rejected and the earlier GEN value is preserved.

A method-body edit leaves the aggregating PD domain and declaration-only model reads unchanged. It also leaves an overlay's semantic declaration projection unchanged when that projection is unaffected. This invariance does not apply to the isolating generator's κ_f input. If a processor inspects executable bodies through Trees, the actual body reads need an explicit proof or the processor is unsupported for reuse; whole-file hashing is not a substitute for the missing aggregate proof. A missing declaration, violated origin contract, unmodelled external read, or unproved execution is reported by processor class, with no module-, route- or project-wide fallback. Fresh processing still supplies outputs and diagnostics; the declaration alone is not evidence that arbitrary processor code is safely reusable. A module with no processor path uses `-proc:none`.

### 3.6 Results are content-addressed

A result is a function of exactly what the attribution read: the file's bytes and name, the options, the processor context, and every entry identity in its proof; not the header shortcuts, which are how the proof is checked and not what the bytes depend on. So it is keyed by that, `ACI = Digest(basename || κ_file || optionsHash || opt<proc> || opt<bodyInputs> || sorted (key || sum))`. Two files anywhere with equal inputs share one `RS|`; two projects holding the same file under different sibling APIs have different proofs, different `ACI`s, and never overwrite each other. The first draft keyed results by `(κ_file, leafSetExt)` and accepted a collision in that case; `ACI` removes it and shares more, not less, because an external set that differs in leaves the file never read gives the same `ACI`. A class file is `CF|Digest(bytes)` and `RS|` holds references, so identical bytes across versions of identical code are one record and "A's class file is unchanged" is one id comparison. Diagnostics are in `RS|`, per file with positions, not in `CF|`. Finding a file's result is: its proof (per project, on its row) gives the keys; the current sums give the `ACI`; `RS|ACI` gives the result, or nothing, in which case the file is attributed.

### 3.7 The reverse index is find-references

`X|G|key|projectKey|module|scope|path`, one empty-valued entry per consumer, so the consumers of `(t, kind, name)` are a prefix range and a consumer joining or leaving is one entry, O(log) in the LOCAL tree, never a list rewritten. "Who calls `T.foo`" is one range read, exact over every attributed body, at member level; the two prefixes `X|G|u8 form || zstr t`, for forms 0 and 1, together select every range consumer of t. `X|D|typeKey|projectKey|module|scope|path` likewise for files that relied on a type's absence. The uses record `U|ACI` adds the offsets, so the LSP goes from file to position without re-attributing. Both are derived from the same collection pass that writes the proof; neither costs a second walk. For LIVE this index is the fan-out: changed keys in, exact candidate files out (appendix D).

### 3.8 Output as a tree

A module scope's valid class files, internal name to `cf`, as a `ContentTree`: its root is the identity of the build output, and writing it to a directory is `Diff` against the root last written there, so a sync touches exactly the files that changed. Tests to rerun after an edit are the same `Diff` over the test scope. This is the first production caller of `Diff`.

### 3.9 Attribution faults are per file and never stop the driver

A file that does not attribute (a body error) has a result with diagnostics and whatever class files javac produced for its other types, a proof over what it did resolve, and a flag. Its consumers are unaffected: they compile against the leaf, which stage 2 made from headers. A file whose header already faulted in stage 2 is attributed anyway; javac reports the same error at the right position.

### 3.10 Nothing in stage 3 is per keystroke in another module

The event and size test of the stage 2 audit, applied to every record here: `C|`, `RS|` and `CF|` change when the file's bytes or its external set change; `X|` and `U|` entries change when a file's proof changes; `OUT|` changes when a class file of the scope changes. A sibling edit changes `routeHash`, `DS|` and `DC|` (stage 2) and nothing in this section. The pool is keyed by the stable sets and is the only thing a sibling edit resets, which costs one classpath open.

## 4. The process

**Precondition:** a committed LOCAL for the project at LAYOUT 4 (appendix A): routes bound, leaves with `A`, definer indexes, stubs, file rows. **Input:** the project model (for processor paths and the file list) and the LOCAL root `LROOT|projectKey`. **Output:** `C|`, `RS|`, `CF|`, `X|`, `U|`, `OUT|` for every file and scope, the LOCAL tree extended over them, and a new bodies root `BROOT|projectKey` naming the stage 2 root it extended (9.1, B.7). `LROOT` is stage 2's and stage 3 never writes it.

### Step 0. LAYOUT 4 (once, before anything in this section)

1. Stage 1 and stage 2 are amended per appendix A: `tail` into `A`, `k` over `res` only, `a` beside `k` in `P|`, `Built` and route elements. FORMAT changes, so a cold boot of MACHINE and LOCAL follows. Invariant 1 of stage 2 becomes equal `k`.

### Step 1. Plan (one thread)

1. Read the LOCAL root, the module records, the source leaf bindings SL| (A.1), the routes with their `(k, a)` sequences, the file rows. No source file is read here.
2. For each module scope, select every file row. Ordinary sources enter Attribute; module-info.java uses the zero-body derivation or Stage 2 header-error result in 2.2.1. (The LIVE loop will pass a subset; the cold driver selects all.)
3. Order: stage 2's topological order of modules. Attribution of a module scope does not depend on its dependencies having been attributed (stubs come from leaves, not from results), so the order is only for the pool reuse and for `OUT|` of a dependency to exist before a dependent's materialisation.

### Step 2. Attribute, per module scope, files in parallel through one pool

1. Pool for `(routeHash, k_own)` of the route and the module: `W` reusable javac contexts, each opened once on classpath = the module's own stub directory ++ the route's entries in route order (jar locations and sibling stub directories), whole. If the module has a processor path, it is bound like a route (its leaves indexed on the spot if MACHINE lacks them) and passed as `--processor-path`, with `-processor` naming the module's declared isolating processors (3.5), each run through the wrapper of C.5; otherwise `-proc:none`. `optionsHash` is computed here from the filtered options (`-A` options included), the release, the source charset (passed as an explicit `-encoding`, never defaulted) and `processorPathHash`. Every task runs under `Locale.ROOT`.
2. For each file `f`: one javac task from a free context over `f` as the only source. javac prefers the given source over the classpath class of the same name, so `f`'s types come from `f`, every other type of the module from its stub. Parse, enter and attribute, then collect observations before generation lowers/mutates the attributed tree. Generate into memory after collection. Diagnostics are snapshotted when emitted, with their original positions. A `Filer` output an isolating generator produces here is captured by the wrapper and not compiled in the task: the generated type is a module source already, and `f` sees it through its stub.
3. Keep the task/context borrowed through collection and generation, then detach every native observation before task cleanup. Merge these with the tree observations before arrangement. At task exit, evict the module's own type symbols (names from `S|k`); the next borrow restores lazy stub entries before its explicit source is entered (C.3). Arrangement only needs the detached observations and the current stored binding.
4. Before generation, the collector (5.2) walks `f`'s attributed tree once and records, for every symbol javac resolved to outside `f`, the `T` ranges of the lookup it walked (the whole closure, with sum zero where a name was absent); the closure headers of every attributed expression type; the member-type and own-package absences a simple name passed; the `D` ranges of the on-demand imports it passed; with offsets for `U|`. For each type `f` declares, the whole method set and header of every supertype in its closure. Entries that name a type of `f` itself are dropped: `f`'s own declarations are in the result, not the proof.
5. The proof is arranged (5.4): the header (`routeHash`, the root sums of `DD|`, `DS|`, `DC|`, `ownR`, and in a processor module the processor context of `f`: `processorPathHash`, `optionsHash`, `configProof(f)` read from `RES|projectKey`), then entries grouped by type with the type's current `oSum` and each range's current sum, read off the current trees through the own-first resolver of 2.3.
6. `ACI = Digest(basename || κ_file || optionsHash || opt<proc> || opt<bodyInputs> || sorted (key || sum))`: the entries, never the header shortcuts (`routeHash`, the index sums, `ownR` are how the proof is checked, not what the result depends on; two routes with the same ranges give the same bytes and share the result). Results: each class file to `CF|Digest(bytes)` (a `CF|` that exists is not rewritten); `RS|ACI` with the references and diagnostics; `U|ACI` with the offsets; `C|projectKey|module|scope|path` with the proof. All in memory in the boot's record map, as stage 2 does with file rows.
7. Reverse entries: for each T/N range key (form included) and D key of the proof, the entry `X|G|key|projectKey|module|scope|path` or `X|D|key|projectKey|module|scope|path`, empty-valued, in the boot's record map.
8. A file that fails to attribute is step 6 with its diagnostics and whatever class files javac produced, and a flag in `RS|`. The scope continues.

### Step 3. Records and tree (one thread, after every scope)

1. `OUT|projectKey|module|scope`: a `ContentTree` over internal name to `cf` for every type of every file of the scope that attributed cleanly; its root in the record.
2. `X|G|key|projectKey|module|scope|path` and `X|D|key|projectKey|module|scope|path`: one empty record per consumer per key, written once, no read.
3. The bodies tree: `apply` over the stage 2 root `LROOT.root` (or, on a rerun, over the previous `BROOT.root` with stage 2's `Diff(BROOT.localRoot, LROOT.root)` applied first) with every record written here except `U|` (key to `Digest(value)`), so the tree is edited, not rebuilt; the previous bodies root moves to history as stage 2's 9.1.
4. Sync, then `BROOT|projectKey` with the new bodies root, the `LROOT.root` it extended, the machine root and the model hash. "Bodies exist for this project" means `BROOT` is present and its `localRoot` equals the current `LROOT.root`; a stage 2 recommit makes it stale without touching it, and the stale `localRoot` is exactly the old side of the `Diff` that names what moved (appendix D).

### Step 4. Materialise (optional, per module scope)

1. The directory last written for the scope has a recorded `OUT|` root (`MAT|projectKey|module|scope|dirHash`, outside the tree). `Diff(previous, current)` names the class files to write and to delete; nothing else is touched. The directory is `java -cp` input for the project.

### Step 5. Ready

Every file has a result and a proof. A reader checks a result by descent on its proof (5.3) and reads `RS|` and `CF|` if it holds. The LIVE loop and the LSP start here.

### What is on disk afterwards

## 5. Pseudocode

Language-neutral. `store` is the LOCAL store; `tree` is the `ContentTree`; `resolver` is stage 2's `DefinerIndex.Resolver` for the route; `sums` is `Sum` mod `p`.

### 5.1 Attribute

```
Attribute(f, scope, pool) -> (result, proof, uses, aci):
    row = F|projectKey|module|scope|f.path                                  // typeKeys, κ, header proof
    context = pool.acquire()                                   // one of W reusable javac contexts for this route state and own leaf
    task = context.task(source = f)                            // classpath fixed per state: own stub dir first, then jars and sibling stub dirs in route order;
                                                               // Locale.ROOT, explicit -encoding; processing per module (C.1); javac prefers the given source
    unit = task.parse(); task.enter(unit); task.analyze(unit)
    (entries, uses) = Collect(unit, task)                      // 5.2, before lowering mutates symbols, trees and end positions
    classes = task.generate(unit)                            // into memory; diagnostics snapshotted at emission time
    entries += native observations retained through generation     // including descriptor queries that failed attribution
    context.evict(own module type names from S|scope.leaf.k); pool.release(context)
    proof = Arrange(entries, scope.route, scope.leaf, scope.module)   // 5.4; detached data only
    aci = Digest(basename(f) || κ || optionsHash || (proof.proc ?? nothing) || (proof.bodyInputs ?? nothing) || sorted (e.key || e.sum) for e in proof.entries)   // no header shortcuts in it
    result = (classes as [(internalName, CF|Digest(bytes))], diagnostics, attributed = no error)
    return (result, proof, uses, aci)
```

The source/options policy is shared with Stage 2 through JavacOptions, including source-level normalization, charset selection, filtered options and optionsHash. The executor snapshots diagnostics when javac emits them, retains native observations through generation, arranges the detached proof and stores CF/RS/U. Any error produces an unattributed result with no class references, even if javac produced partial outputs. Content publication checks existing values and flushes under a store lock, so concurrent equal attributions share their records and a conflicting value cannot overwrite an existing content-addressed result. Compilation itself remains parallel. Mutable C, reverse/output entries and BROOT publication belong to the driver.

**Processor-aware execution.** Attribute.processed prepares its options against the rooted PS invocation, checks processor jar bytes before loading, and runs the selected body processors with in-memory Filer capture. It checks F's source URI and the actual supported configuration lookup chain before and after execution. A moved source/configuration/options snapshot is rejected before publication. The processor host closes before observations are finalized. Every configured isolating generator is compared with its rooted PG/GEN manifest, including known empty output sets and a derivation whose processor did not run in this body task. An uninvoked/no-op processor with no origin and no output does not invent a derivation. Newly captured outputs always require a matching derivation, even if Stage 2 classified the processor as an overlay. Captured output is never compiled in that task or written to GEN/GS.

Attribute returns the fresh ResultRecord, Proof, UsesRecord and processor-class faults. When scope admission, actual processor observations and output conservation all hold, it computes ACI and publishes CF/RS/U. An unsupported fresh result has a rejected proof and no reusable ACI; its class-byte blobs are still content-addressed as CF, but RS/U are not read or published. This retains fresh classes and diagnostics without making unsupported results reusable. The driver must preserve these fresh outputs and faults and propagate any newly discovered processor violation to scope reuse policy; it must not serve an older RS for that scope. An unsupported aggregate rejects scope reuse even though no processor executes in the one-unit body task.

**Implementation boundary.** Both Attribute entry points are tested against fresh whole-module javac on their fixtures. Named type and member declaration queries now recover source annotations/doc comments, declaration order, private members, parameter names and deprecation from rooted PM data. The SOURCE-annotation-driven generator regression now matches native output and passes GEN conservation; a separate deliberately drifting generator remains rejected. Source type-use views now preserve annotations, generic bounds, arrays, receivers, parameters, record types and native type-query rendering. Element origins, executable state and package metadata/presence queries are now covered by native comparison and mutation fixtures. Module package enumeration now retains the actual ordered native answer per processor, phase and queried module in rooted PQ records. It preserves the observation point around lazy classpath discovery, including separate init and round answers, and maps package names back to the current native handles. A second different answer to the same question in one phase revokes admission under the existing replay boundary. Body-only edits preserve this answer; source package-order changes alter the consumed observation. This is a processor-query projection, not module resolution state or a module-info.class derivation input. Completing other module/file queries, remaining package ambiguity/order and public-model edges, persisted general query verification and the complete capability audit remains required. The scope driver now retains aggregate Stage 2 PDIAG output separately from per-file RS diagnostics and identities. A newly discovered processor violation rejects reuse for every result in that scope, including earlier provisional results, while preserving fresh classes and diagnostics. The initial driver and BROOT publication boundary are implemented and tested as described in 5.6. The independent two-sided proof oracle, complete diagnostic policy and module-header validation remain required. The zero-body emitter now matches all own-project descriptors; the current own-project oracle matches all class bytes and 25/26 scopes of ordered diagnostics, with the transitive-automatic-module header warning still missing. These fixtures do not establish full Stage 3 completion.

### 5.2 Collect: what the body resolved through

An attributed-unit walk, with an initial linear pass for own binary names and tree paths, plus native hierarchy query observations from the compiler task. Every node that carries a symbol javac resolved is visited; the rule per node kind is the lookup javac performed.

```
Collect(unit, task) -> (entries: set<Entry>, uses: map<key, [range]>):
    own = types declared by unit (binary names, nested, local and anonymous included)
    for each type D in own, including local and anonymous classes:
        for s in closure(D) \ own: T(s, METHOD, ""); T(s, 0, "")                      // override, abstract, default-clash checks and bridges read every method of every supertype
    for node in unit:
        if node is an expression with an attributed type X (tree.type), X a class or interface type (type arguments included, recursively):
            for t in closure(X) \ own: T(t, 0, "")                                        // every applicability, conversion and inference decision walks these closures,
                                                                                        // whether or not the source names them (f(get()) with get() : A implements I)
        with sym = javac's symbol on node; retain external lookup candidates even when the selected symbol belongs to own:
        case field access or identifier resolved to a field sym on receiver type R (or on a static-imported type):
            for t in lookupPath(R, sym): T(t, FIELD, sym.name); T(t, 0, "")               // every type the field lookup walked; sum zero where t has no such field
        case method invocation resolved to sym on receiver type R, or constructor call on R:
            for t in closure(R): T(t, METHOD, sym.name); T(t, 0, "")                        // overload resolution ranges over the whole closure
            if unqualified: also for every enclosing class E of the call site, for t in closure(E) \ own: T(t, METHOD, sym.name); T(t, 0, "")
        case type reference (declaration, cast, instanceof, class literal, new, generic argument, catch, throws, extends/implements of a local class):
            covered by the expression-type rule above; a declaration's type tree is scanned the same way
        case lambda or method reference targeting functional interface I:
            for t in closure(I): T(t, METHOD, ""); T(t, 0, "")                              // the abstract method set is over the closure
        case switch over enum E: T(E, FIELD, ""); over sealed S: T(S, 0, "") and T(P, 0, "") for each permitted P named
        case simple type name X resolved to a type via java.lang, an on-demand import from package p0, or the file's own package:
            for every enclosing class E of the use, for s in closure(E) \ own: N(memberTypes(s, X)) expected empty   // an inherited member type would shadow it
            if resolved via on-demand or java.lang: D(ownPackage + "/" + X) expected zero
            for p in onDemandPackages(unit) ∪ {java.lang} \ {the package that answered}: D(p + "/" + X) expected zero
        case package-valued simple head Q of a qualified reference:
            D(ownPackage + "/" + Q) expected zero
            for p in onDemandPackages(unit) union {java.lang}: D(p + "/" + Q) expected zero
            for enclosing E, for s in closure(E) \ own: N(memberTypes(s, Q)) expected empty
            for each on-demand member-type import owner s: N(memberTypes(s, Q)) expected empty
        case longer package-valued prefix P of a qualified reference, or a package prefix/target in an import:
            D(P with dots replaced by slashes) expected zero                         // exact type absence, checked against own O and route D; never a package-wide identity
        case static-imported simple name resolved to member of T0:
            for t in closure(T0): T(t, sym.kind, name)                                      // as field/method above
            for other static on-demand imports T2: T(T2, sym.kind, name) expected empty
        if a package/type head occurs in an expression-qualified name:
            record FIELD lookup ranges that could reclassify the head as a variable
            // exclude declaration type positions, class literals and qualified this/super
        uses[entry key] += node range
    for binary type t queried by javac supertype/interfaces, t outside own: T(t, TYPE, "")
    return (entries, uses)

lookupPath(R, sym): R and its supertypes in javac's search order down to and including sym.owner
closure(R): R and every supertype, transitively, as javac's members() would walk it
memberTypes(s, X): the N range with key prefix zstr X || u8 TYPE || zstr s: the member types named X directly enclosed by s, by the names javac reads from InnerClasses (A.1); never a binary-name prefix
T(...), N(...), D(...): an entry naming the tree, the key, and (at Arrange) the current range sum
```

The collector uses javac's attributed symbols and native query observations; it does not implement overload resolution again. Local and anonymous classes of `f` are in `own`, and their inherited method contracts are read just as for top-level classes. Drop facts owned by `f`; retain the external candidate ranges of a lookup even when its selected member belongs to `f`.

An attributed tree alone does not retain every candidate javac tested. For example, `pick(null)` with overloads taking unrelated `First` and `Second` is ambiguous. Making either interface extend the other repairs the error without changing the overload group. The compiler adapter therefore observes native `Types.supertype` and `Types.interfaces` queries and contributes the exact queried binary type headers, including rejected candidates. It does not traverse every candidate signature: a wrong-arity overload does not acquire a dependency on its unused parameter hierarchy. Observations reset per task and repeat on cached contexts; compiler-created pseudo-types are not persisted as binary dependencies. Queries without a syntax position carry an empty span list, not an invented location. The complete two-sided oracle remains required to establish coverage beyond these fixtures.

A local or anonymous class can resolve an identifier to a captured enclosing parameter or local only after looking for fields in the intervening classes. Those exact field groups, including their zero entries, are proof inputs: adding an inherited field can shadow the capture and change emitted bytes. Stop at the common lexical scope of declaration and use. An enclosing method's own parameters and locals are not shadowed by fields of that method owner's superclass. Bodies format 7 fences the earlier proofs that omitted this distinction.

Native functional-descriptor queries also contribute the target's method contract, including when an invalid target leaves an erroneous lambda type. Removing one of two abstract methods can repair that error without changing the target's type header. A class, annotation type or sealed interface is rejected by javac's initial header check, so that rejection does not acquire a whole-method-set dependency. Native observations remain enabled through generation; the adapter detaches them after the callback completes, then merges them with the pre-lowering tree observations while retaining existing source spans. A record/string-concatenation fixture exercises generation-only observations on cold and warm contexts.

Member-type lookup records the exact N range at every visited owner, including a nonempty direct declaration before stopping that branch. Two inherited declarations with the same simple name are ambiguous; removing either moves its recorded range and invalidates the error result even when the enclosing type header stays equal.

Failed simple-type lookups collect exact candidate keys. Arrange binds each key to a D absence if missing, or to its T type-header range if present but inaccessible or ambiguous, and transforms the corresponding U key while preserving its spans. A failed expression qualifier such as `Missing.run()` retains both field lookup ranges and candidate type keys. An inaccessible type is never persisted as an expected absence.

Selected executable types also contribute parameter, return, type-variable and thrown-type headers. A `void` invocation whose declared exception changes from unchecked to checked must invalidate even though its result expression has no class type. TypeMirror dispatch uses `TypeKind`: javac's healthy ClassType also implements the ErrorType interface.

### 5.3 Verify: the descent

```
Valid(proof, route, own, f) -> bool:                                                      // own = the module's current leaf for this scope
    if proof.proc != processorContext(f): return false                                    // includes addition/removal of the processor path, options or configuration;
                                                                                              // checked before any shortcut, because it moves nothing in routeHash or ownR
    if proof.proc != none:
        current = freshlyExecutedOrVerifiedProcessorObservations(f)
        if proof.bodyObservations == none or current == none: return false
        if not reusable(proof.bodyObservations) or not reusable(current): return false
        if inputs(proof.bodyObservations) != inputs(current): return false
    if route.routeHash == proof.routeHash and own.r == proof.ownR: return true               // nothing in the universe moved
    if route.DD.sum == proof.ddSum and route.DS.sum == proof.dsSum and route.DC.sum == proof.dcSum
       and own.r == proof.ownR: return true                                                   // every type still resolves to the same res
    for type in proof.types:
        d = own.O has type.key ? own : resolver.definer(type.key); if d == none: return false   // own-first; the type left the universe
        tMoved = oSum(d, type.key) != type.oSum
        for e in type.entries:
            if e.form == 0:
                if tMoved and rangeSum(T(d), groupKey(e.t, e.kind, e.name)) != e.sum: return false
            else if e.form == 1:
                if rangeSum(N(d), memberTypes(e.t, e.name)) != e.sum: return false             // independent of oSum(type.key); expected empty compares with zero
            else: reject malformed proof
    for e in proof.absent:
        if rangeSum(own.O, e.key) != 0 or rangeSum(D, e.key) != 0: return false               // the type appeared in the module or on the route
    return true

processorContext(f) = none when the module has no processor path, otherwise
                      (processorPathHash, optionsHash, [(path, rangeSum(RES|projectKey, path)) for path in configChain(f)])   // compared as a tuple; zero = no file in that directory
```

Cost after processor-context validation: the routeHash/ownR header shortcut, then the three definer sums plus ownR. If both shortcuts fail, each referenced type needs one definer lookup and one oSum comparison; T ranges need reads only when that oSum moved, while every N range needs an independent range read. Never a walk of `T`, never a per-leaf step. The root sums of the definer indexes are the projection this question needs; their root hashes (the first draft) move on every `k` and would have discarded the shortcut on every unrelated API edit.

### 5.4 Arrange: entries into the descent shape

```
Arrange(entries, route, own, module, f) -> proof:
    proof.routeHash = route.routeHash; proof.ownR = own.r
    proof.ddSum = route.DD.sum; proof.dsSum = route.DS.sum; proof.dcSum = route.DC.sum
    proof.proc = module.processorPath ? processorContext(f) : none                           // 5.3: processorPathHash, optionsHash, configProof(f) off RES|projectKey
    bind candidate type keys through the own-first resolver:
        missing -> D(key) with zero sum; present -> T(key, TYPE, "")
        transform U from candidate D keys to the final T/D keys, merging equal-key spans
    for (t, es) in group entries over T and N by owner t:
        d = own.O has t ? own : resolver.definer(t)                                            // own-first; none: a fault of f, recorded as such
        saved = []
        for e in es:
            sum = e.form == 0 ? rangeSum(T(d), groupKey(e.t, e.kind, e.name))
                              : rangeSum(N(d), memberTypes(e.t, e.name))
            saved.add((form=e.form, t=e.t, kind=e.kind, name=e.name, sum=sum))
        proof.types.add((key=t, oSum=oSum(d,t), entries=saved))
    proof.absent = [n.key for n in entries over D]
    return proof
```

Every sum in the proof is read off the current trees at attribution time, so the proof is exactly "what the result was computed against".

## 7. Properties

### 7.1 What holds

| Property | Statement |
| --- | --- |
| Class bytes are javac's | `Attribute(f)` against stubs produces byte-identical class files and identical diagnostics to a whole-module javac run over the same sources, classpath and options. The oracle is javac, run by the test, never a build tool's output directory. |
| Proofs are complete | Any change to a declaration a body resolved through, or to the hierarchy of any type javac attributed an expression to, fails the proof of every such body. |
| Proofs are minimal | A change to a declaration no body resolved through fails no proof and changes no class byte. |
| Proofs are sums | Every identity in a proof is a root sum of a definer index, an `oSum`, a range sum of `T` or `N`, a range sum of `RES\|` (a configuration file, or its absence), or `ownR`; none is a key; `k` appears nowhere in the proof record. |
| Verification is a descent | Checking a proof is one to four header comparisons when nothing the body read moved, and otherwise O(changed types + their ranges) sums. Never a walk of `T`, never a per-leaf step. |
| `k` is `res`-exact | Equal APIs from a jar and from source give equal `k`; an annotation edit leaves `k`, `r`, every `oSum` and every `routeHash` unchanged and rewrites nodes of `A` and `EA` only. |
| Results are pure | A result is a function of its `ACI` and nothing else; equal class bytes anywhere are one \`CF |
| Sums conserve | After any `apply`, the new sum equals the old sum minus the removed plus the added, at every level. |
| Nothing per sibling keystroke | A change in module A touches no \`RS |

### 7.2 Cost

Let `F` be files, `D` declarations per file, `P` proof entries per file (distinct `(t, kind, name)` resolved through), `W` workers, `C` the classpath open cost.

- `Attribute(f)`: parse, attribute and generate one unit, plus `Collect` in one walk of the attributed tree: O(size of f). With a warm context the classpath cost `C` is paid `W` times per route state, not per file.
- `Arrange`: O(P) own-first definer lookups and range sums, each O(log).
- `Valid`: one or two comparisons when the universe is unchanged (`routeHash` and `ownR`); four or five when every type still resolves to the same `res` (index sums and `ownR`); otherwise O(changed types + ranges of changed types) lookups and range sums. Never a walk of `T`, never a per-leaf step.
- Driver: Σ over files of `Attribute`, parallel across `W`, plus one `apply` over the LOCAL tree of O(records · depth).
- Memory: `W` javac contexts per active route state; results streamed to records; no file's bytes retained past its task.
- `Materialise`: O(changed class files) by `Diff`.

### 7.3 Invariants (tests)

1. **Bytes and diagnostics equal javac.** For every fixture and for jvmd's own modules: class files from `Attribute` against stubs equal, byte for byte, class files from one javac task over the whole module scope with the same sources, classpath and options; diagnostics equal in kind, position and message, deprecation and `SafeVarargs` warnings included.
2. **Stubs suffice for generation.** The same comparison with the real dependency class files in place of stubs: identical. (Stage 2's invariant 14, extended to `generate`.)
3. **Mutation: complete.** Fixture with A and B. For each member of A's API in turn: change its `res` (type, flags, throws, constant value, deprecation). Exactly the files of B whose bodies resolved through that member's range fail `Valid`; the named set is in the test.
4. **Mutation: minimal.** Add a method `K.bar()` that no body resolves through and no type in B extends `K`: no proof fails, no `CF|` changes. Add an overload `K.foo(long)`: exactly the callers of `foo` on `K` or a subtype fail. Add a field `x` to `Sub` where bodies read `Base.x` through `Sub`: exactly those fail. Add `p.X` where a body resolved simple name `X` from another on-demand package: exactly that file fails.
5. **Same module, cross file.** In one module, `B` calls `A.foo()`; change `foo`'s return type: exactly `B` fails, with every route identity unchanged and `ownR` changed. Add a type `X` to `B`'s own package where `B` resolved `X` via `import other.*`: exactly `B` fails. Change a body in `A`: `ownR` unchanged, nothing fails.
6. **Inferred types are proved.** `f(get())` with `f(Object)` and `f(I)`, `get()` returning `A implements I`, `A` named nowhere in the caller's source: remove `implements I` and exactly the caller fails, with every named signature unchanged. The same through a generic method's inferred type argument, a conditional expression, a `var`, and a thrown type.
7. **Subclasses see the method set.** Add `K.bar()` where B has `class S extends K`: exactly the file declaring `S` fails, and its regenerated bytes are identical unless `bar` is abstract or needs a bridge.
8. **Shadowing from the own package and from inherited member types.** A file in package `p` uses `java.util.List` via `import java.util.*`; add `p/List` in a dependency: exactly that file fails. A class extends `Base` and uses on-demand type `Foo`; add member type `Base.Foo` in the dependency: exactly that file fails. Also add `Base.Foo` while keeping `oSum(Base)` equal: the stored form-1 N(Base,Foo)=0 entry must fail after the global shortcuts descend; an equal owner oSum must not skip it. A form-0-only consumer of unchanged Base ranges remains valid. LIVE maps this N delta to form-1 X|G keys independently of O.
9. **Constants.** Change `K.VALUE`: exactly its inliners fail, and their regenerated class bytes differ.
10. **Descent is sound.** Reorder a route so a shadowed type resolves from another leaf: `DC|`'s sum changes and every proof that resolved through that type fails. Add a leaf earlier on the route that redeclares a type: the proofs through that type fail. Swap a leaf for an API-identical one (equal `r`, different `k`): the three index sums are unchanged and `Valid` returns true at the header for every proof.
11. **Descent cost.** For an edit in a type no proof of B touched: `Valid` on every proof of B performs the header comparisons only, counted. For an edit in a type one proof touched: that proof reads that type's ranges only, counted.
12. **`k` exact.** A fixture compiled with javac and indexed by stage 1, and the same fixture through `Φ_src`: equal `k`, equal `a`. Add an annotation to a method: `k`, `r`, `oSum`, `routeHash` of every route unchanged; `a` changed; the nodes written are O(depth) in `A` and `EA`. Mark a method deprecated: `k`, `r` and its `oSum` change, because deprecation is `res`.
13. **Conservation.** For every `apply` on any tree: `root'.sum == root.sum − Σ h(removed) + Σ h(added)`, and for a leaf edit `r' == r + Σ ΔoSum` over the touched types, each `ΔoSum == Σ Δ` over its touched ranges. Asserted in the tree tests and in the driver.
14. **Results are pure.** Attribute with `-g`, then without: two `RS|`, two `ACI`s, and the first is never served for the second. Two projects holding the same file under different sibling APIs: two `ACI`s, both results valid for their project, neither overwritten. Rename a file without changing its bytes: a different `ACI` and a `SourceFile` attribute that differs.
15. **Processors.** A module with Lombok on its processor path: source facts equal class facts for an `@Getter` class (invariant 1 of stage 2 holds with processing on, through the wrapper); `Attribute` of a file using the getter against stubs compiles to javac's bytes. A module with AutoValue: the generated file is a row with origin and `GEN|` id; a change to the annotated file's bytes fails exactly that derivation; a change to a route type the generator read through `Elements` fails it through the originating file's header proof. Replace the processor jar with one of identical API and a changed body: `processorPathHash` moves and every result of the module is invalid; the `k`-based identity would not have moved.
16. **Content addressing.** Two files whose types compile to identical bytes share `CF|` records; attribution of a file twice writes nothing the second time; two files with equal inputs anywhere share one `RS|ACI`.
17. **The given source wins and the pool stays clean.** A file whose module declares a type with the same binary name as one on the route: `Attribute` resolves it to the module's own, from the source when it is `f` and from the stub otherwise, because the own stub directory precedes the route on the classpath; the bytes equal javac's over the whole module. Attributing `f`, then `g`, then `f` again through one context gives the same bytes each time; `W` contexts attribute `W` files concurrently with identical results to serial.
18. **Reverse index and uses.** After attributing a fixture, the prefix `X|G|(form=0, K, METHOD, foo)|project` lists exactly the files that call `K.foo`; adding one caller writes one entry; each `U|` entry's offsets point at the call sites.
19. **Output tree and materialise.** `OUT|` root equals a fresh build over the scope's class files; materialising twice writes nothing the second time; after one file changes, exactly its class files are written; after a file fails, exactly its class files are deleted.
20. **No LOCAL reads before the root beyond stage 2's.** A cold stage 3 reads LOCAL records stage 2 committed (routes, rows, definers, stubs) and MACHINE; it reads none of its own records before it writes `BROOT`. A rerun reaches its own previous records through the previous `BROOT` only, and `LROOT` is never written by stage 3.
21. **Digest is swappable.** The suite passes with two `Digest` implementations.
22. **Order independence.** Shuffle modules and files, vary `W`: identical `BROOT` and records.
23. **Faults at the right grain.** One file with a body error: its `RS|` carries the diagnostics and the flag, every other file of the scope has a clean result, the project has a root.
24. **Attribution-fault proof.** A file that failed attribution has a proof over what it did resolve; fixing the dependency it failed on fails that proof, so the file is re-attributed.
25. **Value permutation fails the proof.** `K` has `public static final int x = 1, y = 2`; a reader of `K.x` is attributed. Exchange the two constants: the keys are unchanged and the multiset of `res` values is unchanged, so the test computes `Σ Digest(res)` over `K`'s facts for both builds and asserts it is equal (the counterexample, computed in the test, no alternative implementation kept anywhere), then asserts that the range sum of `(K, FIELD, x)`, `K`'s `oSum` and the leaf's `r` all differ and exactly the readers of `x` and `y` fail. The same for two methods of equal descriptor-free shape exchanging `throws` lists, and for two types exchanging their member sets. This is why `h = Digest(m || res)` (3.3).
26. **Locale and charset independence.** Attribute under two default JVM locales and two default charsets: identical RS| (bytes and diagnostic messages) and identical ACI, because the task runs under Locale.ROOT and the source charset is passed explicitly and is in optionsHash. A fixture whose source holds non-ASCII text in a string constant, compiled with two declared charsets: two ACIs, two RS|, different ConstantValue bytes.
27. **Processor reuse is per file.** A module of 2,000 files with Lombok on its processor path: edit one @Data class to add a field. Exactly that file is re-attributed, plus the files whose proofs resolved through its changed ranges; every other result is served from RS|, counted. Edit a body in a Lombok file: its own result only. Edit lombok.config in a subdirectory: exactly the files in that subtree re-attribute (configProof moved), with every route identity and ownR unchanged. Delete a lombok.config: the same set, through the absence entry moving from a value to zero.
28. **Aggregating domains.** A module with an aggregating processor over `@Entity`: a body edit in an entity class, or a change to a non-constant field initialiser, leaves `processorElementProjection` and `PD|` unchanged and the processor's `GEN|` valid; a change to a doc comment, an annotation value or a member signature on any member of an entity class moves `processorElementProjection` and `PD|`, since the processor could read it; adding one `@Entity` class is one `PD|` insertion and one rerun of the aggregate; adding an unannotated class changes no PD entry (an independently observed query can still change).
29. **Unsupported means reported, never widened.** A processor jar with no incremental declaration, and one that declares isolating and emits a file with two originating elements: the boot names the processor class, the module compiles to javac's bytes, no RS| or GEN| of the module is served across runs, and no record of the module carries a module-, route- or project-wide identity in place of a read. Grep the store: no such key exists.
30. **Read-set oracle, two-sided.** The test harness instruments javac during Attribute(f) and records two traces: every class outside f whose class-file state javac loaded or completed, and every type or member lookup that returned absent during resolution. Every loaded class is covered by at least one proof entry naming it (a type header or a range in it); every absent lookup is covered by an expected-zero entry (T range, D range or own O). An observation the proof does not cover fails the test and is investigated as a collector gap. It is never fixed by adding a module-, leaf-, route- or project-level identity to the production proof; an observation shown by a focused fixture to be compiler-internal and unable to affect bytes or diagnostics is excluded at the oracle, with the fixture as the record. The oracle is deliberately wider than the proof; the proof never widens to satisfy it. Run over every fixture and over jvmd's own modules.

### A.5a Stage 2 header-range reconciliation (2026-10-06)

A persisted header dependency is `(typeKey, kind, name, sum)`, with `sum = rangeSum(T_definer, groupKey(typeKey, kind, name))` under the own-module-first binding. TYPE selects one type header; FIELD selects a named field range; METHOD selects a named group, or the complete annotation element contract when checking an annotation. Expected-zero member ranges have the same representation as positive reads. Package/type absences remain exact D/O zeros and inherited member-type absences remain exact N `(name, TYPE, directOuter)` zeros. Neither a definer's whole `oSum` nor a containing module identity is the actual read identity.

The LOCAL file codec's header-proof list is `list<(zstr typeKey || u8 kind || zstr name || id sum)>`, followed by `id ownR || list<absence>` as before. `ownR` and DD/DS/DC sums can be validation shortcuts only. Old LOCAL 1/2 file proofs are not decoded into this layout; LOCAL 3 has this proof codec but its legacy reverse keys still require a LOCAL 19 cold rebuild.

Collect source reads after declaration completion and before releasing javac's context. The scanner includes annotations, default values, and final primitive/String initializers even when they have no constant value today; private constants can feed exported constants or annotations. Exclude method/initializer bodies and lambdas. Combine these observations with the implicit type headers used by the emitted facts. Record a named field's winning range and empty ranges preceding it, and each hierarchy header actually traversed to reach a further owner. Qualified member-type lookup likewise consumes the intermediate hierarchy headers as well as N absences, stopping on each branch at a direct declaration. An unresolved header name must retain the corresponding expected-zero observations.

Required mutations: unrelated methods of a type-only or constant-field dependency preserve validity; a consumed constant changes it; an intermediate superclass change invalidates an inherited lookup even when old winners and N zeros remain; a newly available type or constant invalidates its old proof; static on-demand field ambiguities invalidate their consumers; annotation element/default changes invalidate annotation checking while unused annotation constant fields do not. Executable-body-only edits preserve every header proof.

The header reverse representation is `ASCII X|H19| || u8 form || zstr type || u8 kind || zstr name || id project || zstr module || u8 scope || zstr path`, with an empty value. Forms are T=0, N=1, D=2; N uses TYPE/name and D uses TYPE/empty-name. Every positive or expected-zero dependency produces one key per actual compilation unit. Raw current keys are inserted/deleted atomically with LROOT; historical LOCAL nodes preserve the empty values. Prefix lookup reads current keys only, without F, LROOT or LOCAL-membership reads.

The candidate API distinguishes T key/h deltas, N key-presence changes, effective type-presence toggles for D, and exact definer changes for all T/N prefixes of a type. Same-key N/O value replacements do not change zero/absence predicates. Use Diff.content on DC: equal owner oSum can hide a first-provider change affecting N. A loser-only permutation with the same first provider/h requires no reverse work. A pure route permutation must reach T/N consumers even with empty leaf deltas. Validate returned candidates exactly. This primitive does not implement a warm driver or Stage 3's body-read oracle.

Leaf sets are canonical ContentTrees (k → empty, h=Digest(k)); their Merkle hashes key DF/DD/DS and Diff skips unchanged chunks. DF persists all-definer, multiple-definer and disjoint roots, so an exact stored state reopens lazily without scanning its O universe. Changed leaves update touched DF/DD/DS entries through apply. IndexMemo deduplicates exact (kind, leafSet) folds and ordered-route DC work. Parent routes are explicit: own main for tests, first declared sibling main for dependent main, shared JDK external base for roots. Exact DC records are reused first; new routes use ordered Diff, changed/moved leaves' O keys and apply(parentDC). Initial uncached states still pay construction, and canonical binding still visits model entries. Published roots must be readable across workers. The Stage 2 specification defines work counters and repeated-cold/churn regressions for these contracts.

## Appendix B. Record codecs

Primitives as stage 2 appendix B: `u8`, `u16`, `u32`, `u64`, `i64`, `str`, `zstr`, `id`, `list<X>`, `opt<X>`. Big-endian. `|` in a key is the byte `0x7C`.

### B.1 Proof

```
C|projectKey|module|scope|path     = header || opt<bodyObservations> || list<type> || list<zstr absentTypeKey>   // the last proof of this file in this project
header                = id routeHash || id ddSum || id dsSum || id dcSum || id ownR || opt<proc>
proc                  = id processorPathHash || id optionsHash || list<(zstr path || id sum)>   // only with a processor path; the list is configProof(f): one entry per directory on f's chain, sum zero where no file exists
bodyObservations      = u8 rejected || list<(str processorClass || opt<bytes modelAnswers> || u8 declared || u8 observed)> || list<str configuredProcessor> // invocation order and detached actual answers; configured names are admission metadata
bodyInputs            = list<(str processorClass || opt<bytes modelAnswers>)> // same order; capability governs admission, not result content
type                  = zstr typeKey || id oSum || list<entry>
entry                 = u8 form || zstr t || u8 kind || zstr name || id sum
                        // form 0: T member range, key as Keys.groupKey; form 1: member types named name directly enclosed by t: the N range zstr name || u8 TYPE || zstr t (A.1), never a binary-name prefix
                        // sum = form 0: rangeSum(T, groupKey(t,kind,name)); form 1: rangeSum(N, memberTypes(t,name)); own-first; zero for an expected-empty range
                        // oSum gates form 0 only. Form 1 is checked independently after global shortcuts fail.
```

There is no leaf level and no `k`: a type is resolved at verification through the definer indexes, and the header's index sums decide whether that resolution can have changed at all. For form 0, `kind` is `Keys.TYPE` (0), `FIELD` (1), `METHOD` (2); `name` empty means the whole kind, and `kind = 0` with empty name is the type fact. For form 1, `kind = TYPE` and `name` is the exact member simple name; the N prefix is `zstr name || u8 TYPE || zstr t`. Sorted: types by typeKey, entries by key bytes, absences by key, so the record is a function of its content.

Body processor observations preserve the invocation order, class names, capability and detached public-model query transcript. The transcript contains actual query arguments/answers, opaque reference relationships, visitor dispatch and round answers; it never substitutes a whole leaf A, module source hash or generated-output root. An absent transcript denotes a tested native overlay or a processor javac did not initialize. An empty body observation list is distinct from missing observations, including scopes whose only configured processors are aggregating and excluded from body tasks. Every recorded body invocation must be classified isolating and reusable; an aggregating invocation cannot be admitted as a body result. Capabilities gate admission but are excluded from the result input encoding. Body records use version 4 (bodies 6). Configured processor names include aggregates that do not execute in body tasks; they select exact global capability-history reads and are excluded from bodyInputs. Every observation names one of these configured processors. The rejected flag records failed scope admission/output conservation even when the invocation list is empty; it is not part of bodyInputs. Earlier body-record versions require cold reconstruction.

`ProcessorHost.bodyObservations()` is available only after closing a body host, so unclosed Filer writes and other late violations are finalized first. The returned records are immutable snapshots. `Proof.valid` without supplied current observations always rejects a processed proof; its explicit observation overload checks both admission flags, exact observed inputs and the global violation history of each configured processor before any route/own/index shortcut. `Proof.aci` refuses processor-bearing results with missing or unsupported observations. The current observation argument must come from a fresh admitted invocation or verified queries in the current environment, never by copying the old proof. Output conservation against GEN is a separate necessary check. Attribute.processed now combines these checks for fresh invocations and publishes only reusable results. These APIs do not yet implement the persisted query verifier or the complete processor capability/model audit.

Native `Object.equals` with Object's unchanged implementation compares already-observed handles; incidental identity-hash-table collision checks add no model fact. Overridden equality (including structural array types and annotation values) remains a query. The broader processor capability audit remains necessary, including processors whose outputs depend on allocation identity or unmodelled inputs; repeatable observations alone are not a complete admission proof.

### B.2 Result

```
RS|ACI                = u8 attributed || list<(zstr internalName || id cf)> || list<diagnostic>
diagnostic            = u8 kind || u32 startOffset || u32 endOffset || str code || utf16 message   // kind: 0 error, 1 warning, 2 note; messages in Locale.ROOT
CF|cf                 = classBytes                                 // cf = Digest(classBytes)
optionsHash           = Digest(filtered javac options as passed, -A options included || u8 release || str encoding || id processorPathHash)
processorPathHash     = Digest(ordered bh of the processor path's jars)   // full byte hashes from P|, never k: a processor's bodies execute
configProof(f)        = ordered (zstr path || id sum) over configChain(f)   // sum = Digest(path || κ) of the file, or zero; read from RES|projectKey (appendix F)
ACI                   = Digest(str basename || id κ_file || id optionsHash || opt<proc> || opt<bodyInputs> || (key bytes || id sum) for each proof entry, sorted)   // never routeHash, index sums or ownR
```

`attributed` is 1 when javac reported no error. Class files are listed for every type `f` declares, nested, local and anonymous included, in internal-name order. Diagnostic order and repeated messages are retained. Positions are javac's UTF-16 character offsets into the decoded source, not byte offsets. The u32 value 0xFFFFFFFF represents Diagnostic.NOPOS (-1); other values retain their unsigned offset. This matters for supplementary characters and non-UTF-8 source encodings.

### B.3 Reverse

```
X|G|key|projectKey|module|scope|path   = (empty)        // key = u8 form || zstr t || u8 kind || zstr name, as the proof entry; one record per consumer
X|D|typeKey|projectKey|module|scope|path = (empty)
```

The prefix `X|G|u8 form || zstr t` selects consumers of that form in t; the union of the form-0 and form-1 prefixes is every range consumer of t; `X|G|u8 form || zstr t || u8 kind || zstr name` every consumer of one range; the trailing `projectKey`, `module`, `scope` and `path` narrow to one source compilation. The consumer suffix is `id project || zstr module || u8 scope || zstr path`. One record per consumer, so a file joining or leaving a range is one entry in the LOCAL tree and a hot range (`Object.toString`) is never rewritten as a list.

Body consumers are members of the committed BROOT tree, not merely raw storage keys and not members of LROOT. Diff(T/N/D) maps changed keys to X|G/X|D prefixes and seeks those prefixes without scanning C or F records. Cached per-project BROOT membership filters unreachable keys from old body generations. A BROOT that names an older LROOT is still the source of old consumers while the caller validates the delta against the new LOCAL state; staleness must not hide the consumers that need checking.

### B.4 Uses

```
U|ACI                 = list<(u8 tree || key bytes || list<(u32 start || u32 end)>)>
```

Tree 0 is T, tree 1 is N, tree 2 is D. For T/N, the remaining key is `zstr type || u8 kind || zstr name`; for D it is `zstr type`. Thus the complete uses key is the proof range key (including form), or `u8 2 || zstr absentType`. The same namespaced keys and their expected sums, including zero for D, are sorted in ACI. Each use has sorted distinct UTF-16 offset ranges in `f` where javac resolved through it. Derivable; outside the bodies tree.

### B.5 Output and materialised

```
OUT|projectKey|module|scope       = id root.hash || id root.sum || u32 count || u8 level     // a ContentTree: key zstr internalName, value id cf, h = cf
MAT|projectKey|module|scope|dirHash = the OUT value last written to the directory whose canonical path digests to dirHash
```

`OUT` covers the class files of files with `attributed = 1` only. `MAT` is per machine and outside the tree.

### B.6 FORMAT

```
FORMAT = <current LOCAL FORMAT, including full javac runtime version and locale=root>;bodies=7
```

`bodies=7` fences proofs that omitted inherited-field absences for captured parameters and locals. ### B.7 Bodies root

```
BROOT|projectKey = str FORMAT || id bodiesRoot || id localRoot || id machineRoot || id modelHash
                   // bodiesRoot: the tree of 9.1 (stage 2's records plus C|, RS|, CF|, X|, OUT|); localRoot: the LROOT.root it extended
```

A separate root so that each stage owns its own commit: stage 2's warm path rewrites `LROOT` without knowing stage 3's records, and stage 3 learns that it happened from `BROOT.localRoot != LROOT.root`. `Diff(BROOT.localRoot, LROOT.root)` is then the exact set of stage 2 records that moved, which is the Δ that drives `X|` lookups and `Valid` (appendix D). One root for both would make every stage 2 recommit a rewrite of stage 3's history, or make stage 2 depend on stage 3.

## Appendix C. javac

### C.1 The task

```
task = pool.getTask(fileManager, diagnostics, options, null, [f])   // the context was created with Locale.ROOT; diagnostics are machine-independent
  options: -source <release> as stage 2 C.1; -Xlint:-options; -implicit:none; -encoding <model's, else UTF-8>;
           --class-path <own stub dir> ++ <jars and sibling stub dirs in route order>; --system <jdkHome>;
           -proc:none when the module has no processor path, else --processor-path <bound processor leaves' locations>, -processor <the module's declared isolating processors, each wrapped (C.5)> and the module's -A options;
           -parameters, --enable-preview and the rest of module.javacOptions filtered as stage 2 C.1 (no -d, -s, -h, classpath, release, system)
  -g as the module passes it: debug attributes are part of the class bytes javac would produce, so they are part of the result
unit = task.parse(); task.enter(unit); task.analyze(unit)
observations = Collect(unit, task)                         // before lowering changes the attributed tree
task.generate(unit)                                      // in-memory class files; Filer outputs captured, never compiled here
```

The in-memory file manager forwards every read to the standard one and captures class file writes. No file is written to disk by `Attribute`. Source input is an immutable byte snapshot, decoded with the task-bound javac BaseFileManager and its explicit charset. Decoding errors use the same task Log, preserving native diagnostic positions and messages and preventing output on an error. Reopening the path or decoding with replacement via new String(bytes, charset) would respectively permit a changed input or erase the encoding diagnostic. The pool owns the snapshot and releases its decoder binding at task exit. Attribute verifies the snapshot digest and source basename against the F row before compiling, and checks that the pool's route/own binding, charset and effective options match the identities used for arrangement and ACI.

### C.2 The pool

`com.sun.tools.javac.api.JavacTaskPool` with `W` contexts per `(routeHash, k_own)`, one per worker, because a javac `Context` serves one task at a time: javac's own reuse mechanism, built for exactly this (jshell and the JDK's own tools use it). The existing routeHash names the ordered sequence of every route leaf, and k_own names the module's own leaf. Unordered external/sibling leaf sets cannot key the pool: swapping two jars that define the same binary name leaves both sets unchanged but changes the winner javac must load. No new identity is needed, and this pool binding does not enter ACI or widen semantic proofs. Each context's symbol table of classpath types persists across the tasks it runs; a task's own compilation unit is discarded at the end, and the own module's types are evicted by name after each task (C.3). Each context's file manager is opened once on the classpath of 3.1, own stub directory first, then the route in route order, so the cost is `W · C` per key. When either identity changes (a route reorder, sibling edit, dependency bump, or own-module API edit that moved `k_own`), the loaded symbols or their precedence can be stale and all `W` are dropped; the next files pay the opens again. In a cold stage 3 `k_own` is constant per module and scope, so the key never changes within a scope. `--add-exports jdk.compiler/com.sun.tools.javac.api` is already in `jvmd-boot`'s pom from stage 2.

### C.3 Own-minus-f

Every stub of the module's own leaf is on the classpath, first, `f`'s own types included, and `f` is the only source. The order matters twice. javac uses an explicitly given source over a classpath class of the same binary name without a diagnostic; this is the ordinary incremental case of compiling a changed file with the output directory on the classpath, and every build tool relies on it. And between two classpath entries declaring the same binary name javac takes the first, so the own stub directory precedes the route: a module's own type wins over a route type of the same name exactly as it does in javac over the whole module, where sources precede the classpath. So `f`'s types come from `f`, every other type of the module from its stub, and a route type of a clashing name is shadowed, with no per-file directory and a classpath that is constant per pool key. The pool must not carry `f`'s types over as classpath symbols into the next task, or into a later re-attribution of `f` itself: after each task the context evicts the module's own type symbols (names from `S|k`). `JavacTaskPool`'s reusable context already discards classes compiled from source between tasks; the eviction extends that to the own-module stubs it may have loaded. Invariant 17 (the given source wins and the pool stays clean) tests both halves and the shadowing. Package scopes also survive native context cleanup: removing a name from Symtab alone makes its next lookup fail. Eviction therefore removes each loaded own symbol from its owner scope too, then the next borrow re-seeds only those names as lazy class symbols backed by the already known own stub files. It does not invalidate or re-scan whole packages. Dependency symbols remain cached. The pool closes file-manager-created classloaders as well as the file managers, because the reusable JavaCompiler's close method deliberately does nothing; otherwise a classloader can retain jar handles after the pool is dropped.

### C.4 Collect: javac's symbols

The collector runs over `task.analyze`'s output tree before `task.generate`; generation lowers/mutates that tree and can clear the task context. On every `JCFieldAccess`, `JCIdent`, `JCMethodInvocation`, `JCNewClass`, `JCMemberReference`, `JCLambda` and type tree, `TreeInfo.symbol(tree)` (or `Trees.getElement(path)`) gives the symbol javac resolved. From a `MethodSymbol` or `VarSymbol`: `owner` is the declaring type; the receiver type is the static type of the qualifier (`site`), from `tree.selected.type` or the enclosing class for an unqualified name. `closure(R)` is `types.closure(R.type)` for classes, plus interfaces; `lookupPath` is the same list cut at the owner. Deprecation is `sym.isDeprecated()` (and `forRemoval` from the annotation). On-demand imports are `unit.getImports()` with `isStatic` and a trailing `*`; `java.lang` is always one. Enum constants are `VarSymbol`s with `ENUM` flag and are FIELD groups. A `JCLambda`'s target is `tree.type.tsym`; the functional descriptor's group is `(I, METHOD, "")` over the closure.

Nothing here re-implements resolution. An erroneous node can still consume native candidate, hierarchy, member-type or functional-descriptor queries. Those observations remain in the proof even when no selected symbol survives in the attributed tree; the file's `attributed` flag is 0 if javac reports an error.

### C.5 Processors

Every processor runs through jvmd's wrapper, in the stage 2 header compile and in `Attribute(f)`: a delegating `Processor` whose `init` hands the real processor a `ProcessingEnvironment` whose `Filer` records each created file with the processor class and the originating elements the processor passed, and whose model-query methods record actual arguments and answers. A Gradle declaration alone does not establish compatibility or prove all inputs; supported behavior is checked as specified in 3.5 and F. Lombok reaches javac's internals by reflecting over the wrapper's fields for the `JavacProcessingEnvironment` delegate, so the delegate is a field. In the header compile the recorded outputs become generated rows with origin and `GEN|` id, the recorded originating-element counts are checked against the declaration (`PROC|`), and `PD|` is built from the elements the aggregating processors were handed. In `Attribute(f)` only the scope's declared isolating processors run, selected in PS order after matching processor bytes and effective options; an overlay processor rewrites `f`'s AST, which javac then attributes and the collector walks, so its semantic reads are ordinary entries and `f`'s result holds the bytes javac produces for `f`'s types after processing; a generator's `Filer` output is captured and not compiled in the task, because the generated type is a module source with a stub already; its complete output manifest must match the corresponding `GEN|` root reached through `PG|`, comparing captured byte digests with content ids without rereading `GS|` blobs. Aggregating processors never run in `Attribute(f)`: in a one-unit task they would see one element of their domain and produce a different output. The processor context `(processorPathHash, optionsHash, configProof(f))` is in the header and, as the proc field, in `ACI`; the configuration chain for Lombok is `f`'s directory and its parents to the root or a `config.stopBubbling`, each directory one `RES|` lookup.

## Appendix D. Deferred, and what each takes from here

**The LIVE loop.** Consumes `Valid` (5.3), `Attribute` (5.1), `Diff` and the reverse index, and nothing else from stage 3. Its work is driven by the change, never by the project: an edit changes a leaf; `Diff` of the old and new definer indexes names the types whose definer or `res` changed; `Diff` of `O` names the types whose `oSum` moved; a range diff of `T` within each such type names form-0 ranges that moved. Independently, `Diff(N_old, N_new)` names changed direct-member-type prefixes, mapped to form-1 reverse keys `(1, outer, TYPE, innerName)`, even when the outer oSum did not change. This N delta is not gated by the outer O entry. Processor-domain and configuration changes follow their recorded proofs. Those keys go through `X|G` and `X|D` to the exact candidate files, `Valid` confirms each (most fail at a range, a few pass because the change cancelled), and `Attribute` runs on the failures. Cost is the size of the semantic delta times its fan-out, independent of the project's size. Its own document covers the overlay of unsaved edits, the leaf edited by `apply`, the collapse on save by equal `k`, and the pool's lifetime. A body-only edit is one where every `oSum` of the edited file's types is unchanged; whether it is also HotSwap-legal needs the class file's member schema (names and descriptors, private members included, since those are not facts) to be unchanged, which is a projection of the class file LIVE will define; comparing whole class bytes cannot tell, since a body edit changes them. Not a stage 3 record, and not claimed here beyond the `CF|` against the old.

**Warm boot.** The same engine as LIVE with the disk as the event source: rows whose `κ` or stamp changed are the edits; their leaves are re-facted and the same `Diff` to `X|` to `Valid` to `Attribute` chain runs from there. Nothing scans every proof asking "are you still valid"; the question is "what changed, and who read it". Nothing to design here beyond LIVE.

**The LSP.** Diagnostics from `RS|`; go-to-definition through the definer index to a file row or a jar entry; find-references from `X|G` and `U|`; hover from `res` and `A`; completion by attributing the open file at a position through the pool (the one place attribution runs on an unsaved buffer, which LIVE provides). Rename is references plus edits. Nothing in the protocol layer changes a record.

**The provider.** The project model from one Maven invocation over the reactor after `generate-sources`: compile source roots, classpath, processor path and options, release, per module and scope. Hard requirement before any work repo; a Maven extension or a plugin, not per-module forks. Gradle later.

**Running and tests.** `Materialise` per scope and `java -cp`. Affected tests after an edit: `Diff` of the test scope's `OUT|` plus `X|G` closure into test files. A test runner integration is product work on top, not a stage.

**Cross-machine sharing.** Every `N|`, `L|`, `S|`, `ST|`, `DD|`, `CF|`, `RS|` and `U|` record is a pure function of content; a team server can hold them and a fresh machine fetch instead of compute, verifying digests. `C|`, `X|` and `OUT|` are a project's own index of its files and stay with the project. A transport, not a design change.

**Garbage collection.** Section 9.2.

## Appendix E. Review rounds

Each round adds numbered items naming the section they change, as stage 2's appendix E did. The first PR expected is appendix A alone (LAYOUT 4); the second is stage 3 proper.

### E.0 Review of the first draft, before any PR

1. **`L` was not a function of `k`** (appendix A, 3.4). `E` carried annotation-type edges derived from `tail`; two leaves with equal `res` and different annotations would have had equal `k` and different `E` roots in `L|k`. Those edges move to `EA`; `a` covers `A` and `EA`; stage 2's kind 7 takes targets from both.
2. **The descent's top-level and leaf-level skips were unsound** (3.3, 5.3, B.1). `R` is order-free, so a reordered route passed with resolution changed; `r` of a leaf says nothing about a type changing hands to an earlier leaf. The proof header now carries `routeHash`, `R`, `RA` and the `DD|`, `DS|`, `DC|` roots; the leaf skip is allowed only when the definer roots are unchanged. Invariant 8 tests both failure modes.
3. **Own-minus-f contradicted the pool** (2.2, 3.1, 5.1, 5.5, C.3). A per-file classpath defeats a shared javac context. Replaced by: every own stub on the classpath, `f` as the only source, javac's preference for the given source, and eviction of the own module's type symbols after each task.
4. **Compile options were in no key** (2.2, 2.4, B.1, B.2). `-g`, `-parameters`, preview, processor set change the bytes without moving `κ` or the external set. `optionsHash` joins the `C|` and `RS|` keys. Invariant 11.
5. **Same-package and inherited member types shadow on-demand imports** (3.2, 5.2, C.6). Absence entries now cover the file's own package and the member types of every enclosing class's closure, not only other on-demand packages. Invariant 6.
6. **Type references need the closure, not the header** (3.2, 5.2, C.6). Every subtyping test walks the chain; a change two levels up changed no byte of the referenced fact. Unqualified calls likewise walk the enclosing classes' closures.
7. **A declared type depends on its supertypes' whole method set** (3.2, 5.2, C.6, 1). Override, abstract-method and default-clash checks and bridge generation read every method of every supertype; `(s, METHOD, )` for the closure. The minimality claim is restated: callers of `K` are untouched by a new `K.bar()`, subclasses of `K` are re-attributed, correctly. Invariant 5.
8. **Minimal warning state is in res; full retained annotations remain in A** (2.1, 3.4, appendix A). javac warning state belongs in res so stubs and semantic proofs cover it. ### E.4 Systematic check: mathematical, architectural, operational

The check that found these was mechanical: list every input of the javac task `Attribute(f)` runs, and for each ask which recorded identity moves when it moves (the table in 2.2). Six holes.

1. **Sums did not bind values to keys** (3.3, A.1, A.3, 2, invariant 25). `h = Digest(res)` makes every range sum a sum over values alone, which is invariant under permuting the values among the keys: two constants exchanging values left the range sums, `oSum` and `r` unchanged. Now `h = Digest(m || res)` (and `Digest(m || tail)` for `A`), so a range sum is the identity of the key-to-value map over the range. The definer indexes and stubs already had this shape. The same rule was applied to `moduleSourceSum`, which E.5 then removed for a different reason.
2. **`ownR` was in `ACI`** (5.1, B.2, step 2). `ownR` is a header shortcut for `Valid`, not an input of the bytes: two files with equal entry sums get equal bytes whatever the rest of the module did. With `ownR` in `ACI`, every unrelated API edit in the module would have produced a new `ACI` and a re-attribution that then found an identical result. `ACI` is now over the entries only: `basename`, `κ`, `optionsHash`, the processor context, and the sorted `(key, sum)` pairs.
3. **Locale and charset were unstated inputs** (5.1, C.1, B.6, 9.1, invariant 26). javac's diagnostic text depends on the default locale and the bytes of a string constant depend on the source charset; neither was in FORMAT, `optionsHash` or the proof. The task runs under `Locale.ROOT` (`locale=root` in FORMAT) and `-encoding` is always explicit and in `optionsHash`.
4. **Classpath order was unstated** (3.1, 5.5, C.2, C.3, step 2). javac takes the first classpath entry declaring a binary name; a module type clashing with a route type must win as it does in javac over the whole module. The own stub directory is first, then the route in route order, and the pool key gains `k_own`, since a context can hold symbols from the own leaf as well as from the route's leaves.
5. **Stage 2's header proof had no absences** (A.1). Kinds 7 and 8 prove that what resolved still exists; nothing proved that no type had appeared earlier in a header's lookup (own package over an on-demand import, an inherited member type). The header proof gains the absence entries of 2.3, collected by the same rule as 5.2, over the same universe: own leaf first, then the route, because a type added in another file of the same module shadows a header's on-demand import too. The own leaf's r goes in its header as ownR does in stage 3. This is the stage 2 twin of E.3 item 1.
6. **One root for two stages** (9.1, step 3, 5.6, B.7, invariant 20). Stage 3 rewriting `LROOT` made every stage 2 recommit a rewrite of stage 3's history and made "bodies exist" undecidable. `BROOT|projectKey` holds the bodies root and the `LROOT.root` it extended; `Diff` between the two roots is the stage 2 change set that drives reuse.

### E.5 Processors were a black box

E.3 and E.4 bound every processor-bearing result to `moduleSourceSum` and `moduleResourceSum`: any source or resource edit in the module invalidated every result of the module. That was correct and it was the coarse invalidation this project exists to remove, justified by "a processor could read anything" rather than by what a processor read. The method that found E.4's holes, asking what the task was handed, finds this one too: `Attribute(f)` hands javac one unit, so binding `f`'s result to every other unit in the module contradicted the task itself. Removed, and replaced by the same rule as everything else (3.5, C.5, appendix F, 2.2, 2.3, B.1, B.2, invariants 15, 27, 28, 29, Do-not 12):

1. An overlay processor's semantic reads are already entries: javac attributes the tree it rewrote and the collector walks that tree. Its context is `processorPathHash`, `optionsHash` and `configProof(f)`, the `lombok.config` chain as per-directory lookups with absences, against `RES|projectKey`.
2. An isolating generator's output is a `GEN|` derivation over its originating file: `κ_f` is the grain because `Filer`'s originating elements are defined at compilation-unit grain, and the file's header proof entries are its semantic reads.
3. An aggregating processor depends on the root sum of `PD|`, the tree of the elements it aggregates keyed by their units' declaration skeletons (κ\_decl: what javax.lang.model exposes of another unit, bodies excluded), and reruns over that domain. A first draft keyed it by whole-file κ, which contradicted invariant 28; the worker's question caught it.
4. The support contract is the declaration processors already make for Gradle (`isolating`, `aggregating`), observed through the same `ProcessingEnvironment` wrapper Gradle uses; overlay versus generator is a recorded capability per processor class, established on fixtures, not inferred from one run. Undeclared or contract-violating processors are unsupported for reuse and reported by class; nothing coarser stands in.
5. Route `R` and `RA` leave the processor context: anything a processor read on the route reached the attributed tree or the originating file's header, and is an entry there.

One hot context also processes package-info rows from successive equal-T snapshots before consuming, deleting and rebinding metadata: unread comment/body edits preserve the result, a consumed annotation edit moves it, and deletion removes the annotation without a source reread. Equal comment text with different native block/end-of-line kind changes PD.

Source type-use regressions compare fresh native class bytes and ordered diagnostics for generic bounds, multi-dimensional arrays, wildcards, explicit and enclosing receivers, throws, private members, records, inherited substitutions, repeated annotations and mirrored class values. Hot-context reuse after deleting the metadata source preserves ACI under unread type-use/body edits and changes it for a consumed type-use annotation, then restores the first result when rebinding the first snapshot. These query views require no new persisted codec. Repeated allocating type-factory and annotation-proxy queries in a single phase now replay their captured occurrences, retaining distinct or reused opaque model handles and mirrored class-value exceptions. The broad type-use scan exercises these repeated queries. These passing fixtures do not establish universal processor admission or support for arbitrary allocation-sensitive behavior.

The processorElementProjection comes from the completed source Element model, with the fields and exclusions specified in 3.5. Annotation values retain explicit presence, effective defaults and native origin; declaration order, parameter names, doc-comment absence and kind, element origin and executable bridge/compact/canonical state are observable. SOURCE retention and source-only declaration information make this distinct from A, while its body exclusions make it distinct from κ_file. A body-only edit preserves the PD entry, root hash and root sum. Changing a supported annotation, annotation value or processor-visible declaration changes membership or the projection. A processor that reads bodies needs a proved body read or is unsupported; it never widens PD to κ_file.

The generator identities are length-framed encodings of:

```
isolating:
    processorClass, processorPathHash, optionsHash,
    originPath, κ_origin, configProof(origin),
    sorted (form || rangeKey || sum) header observations,
    modelProof(processor, origin)

aggregating:
    processorClass, processorPathHash, optionsHash,
    rootSum(PD), modelProof(processor)
```

Header form 0 is T, form 1 is N, form 2 is D, including expected-zero observations. Model proofs encode actual ordered public query arguments and answers, not a containing type/module's annotation sum. The same binary API may carry different annotation metadata; a query that observes that metadata must change the derivation even when T and the header proof stay equal.

An isolating processor is also executed with a fresh classloader and instance for each origin against captured round inputs and phase-specific model answers. Round annotation names, roots, matches and source provenance are captured while javac is live; replay never calls native Element/Elements/Types/Trees to recover a missing answer. It must reproduce exactly that origin's native generated path-to-bytes map, including empty outputs. An unobserved/ambiguous query, exhausted allocation sequence, non-provenance output, unsupported resource/body read, or differing output rejects reuse with the processor class and reason. This checks attribution of shared/cached model reads without replacing them with all reads from the native batch. It does not establish arbitrary processor determinism or audit every possible external input merely because a replay succeeded.

GEN separates three identities: processor input derivation, exact output set, and individual output bytes. Distinct derivations can share GS blobs and ContentTree nodes. Multiple files from one origin/domain share the same GEN reference. The manifest's hash answers exact equality and Diff answers additions/removals/changes; its algebraic sum is available structurally but is not consumed as an invented proof. Empty derivations have an empty manifest. If an identical derivation is observed with a different output root, the existing GEN is preserved and the processor is marked unsupported.

Lombok's tested overlay path keeps the native ProcessingEnvironment delegate in a field for its supported unwrapping. A Gradle declaration is a contract to verify, not proof that every declaring processor is supported. Unknown declaration mutation, body access outside a tested overlay, resources without proofs, or other unmodelled inputs must be named unsupported. No broad identity is an alternative.

Known allocating public contracts use per-query, per-phase occurrence sequences: Types array/declared/wildcard factories, member/supertype projection, erasure/capture/annotation stripping; AnnotatedConstruct annotation-proxy getters; and array/nested-annotation members of annotation proxies. Capture retains each observed result, exception and opaque-handle alias, even when two consecutive occurrences return the same handle. Each isolated invocation starts with independent cursors. A replay cannot consume beyond the captured sequence, synthesize an allocation or recycle the last answer. Ordinary lookups and scalar answers still require one consistent answer per phase; a changed opaque lookup handle is not classified as allocation. Captured replay never re-enters the native model. The ordered answer-proof byte codec is unchanged, and no module/route/domain identity is added.

**F.2 Tests**

1. Lombok through the wrapper produces the expected injected declarations; source facts equal the native javac class facts.
2. AutoValue outputs carry exact originating-file and GEN references. Repeating unchanged inputs produces equal ids, roots and bytes and writes no duplicate GEN/GS/tree nodes.
3. Configuration additions, changes and deletions at two directory depths affect only the corresponding per-file configuration chains, including previously absent files.
4. An aggregate over @Entity preserves PD hash/sum and GEN under method-body and non-constant-initializer edits; annotation/default/value/signature/member/doc-comment changes move the appropriate projection, and domain membership changes are exact insertions/removals.
5. Missing declarations, invalid origin counts and unproved body/resource reads report the processor class and publish no reusable derivation. No module/route/project identity replaces a missing proof.
6. API-identical processor jars with different bodies change processorPathHash and the header invocation.
7. Multiple generated outputs share one manifest; equal outputs across derivations share blobs/nodes. Diff between output roots equals the generated-file rows added, removed or changed.
8. Repeating a derivation must reproduce the exact root hash. A conflicting output set never overwrites the earlier GEN.
9. Two origins served through a processor's static model-read cache each receive an independent proof. Changing a read binary annotation changes both derivations even when T is unchanged; editing only one origin's body changes only that origin's κ-based derivation.
10. Cross-origin mutable state that changes isolated output, unobserved queries and native-model access after capture cannot silently validate. The processor is named unsupported.
11. Processor diagnostics preserve order, duplicate messages, source positions and filtering under Locale.ROOT; replay does not publish them twice.
12. Repeated allocating queries preserve distinct/reused model-handle relationships and mirrored exceptions in replay, with independent cursors per origin and phase. Missing or exhausted occurrences reject reuse. A batch-sensitive processor that requests an extra allocation when isolated must not receive a recycled handle that makes its output appear isolating. Fresh generated files remain available, but no GEN derivation is published for that processor.

**Implementation boundary.** The current cold-boot path runs native processors freshly, captures the queries, checks isolated replay and deduplicates exact manifests. It does not skip a processor invocation using a persisted model-query verifier; such a skip would additionally require that verifier and is not proved by the current replay. The body-task component now captures outputs outside javac rounds; scope-specific selection and rooted manifest comparison are implemented and tested from a fresh Stage 2 commit through body capture. The body proof codec and ACI now bind finalized ordered model observations and reject missing/unsupported observations before every resolution shortcut. Attribute.processed now binds source/options/configuration, runs capture, checks rooted output conservation and either publishes CF/RS/U or returns an explicitly unsupported fresh result. Source type declarations, package headers and package presence are now persisted in PM and decoded independently of T/A. The source-side processor query adapter covers the tested type/member declarations, type-use views and package queries. Completing module/file views, the remaining package ambiguity/order and public-model edges, auditing every admitted processor input, implementing persisted query verification, completing module-info handling and proving all remaining full-stage invariants remain required; these records and passing fixtures do not claim the entire stage is finished.
