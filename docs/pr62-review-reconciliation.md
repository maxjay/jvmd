## Follow-up review: materialisation and metadata admission, 2026-10-07

The F19/F20 implementation was independently checked. MAT alone previously could not account for files installed by a failed intermediate target. Output now persists MATP before visible class changes, stages verified payloads one at a time beneath the reserved `.jvmd-output` directory, completes a pending target on reopen, and only then applies the requested target. The last committed MAT is not a claim that the current directory is complete while MATP is nonempty. The successful MAT update and pending clear are atomic in the store. A bounded JVM lock set and an OS file lock cover the entire operation. The lock records scope plus a store-owned random ownership token: a different store cannot silently start an independent history in that directory. Untracked files remain untouched. Recovery replays exact Diff paths and deterministic staging names, without scanning the output directory. Disk space is proportional to the changed output set; payload heap is bounded by one CF. This establishes ordinary I/O/reopen recovery, not power-loss filesystem certification. It cannot infer partial writes made by an older implementation which left no pending record.
