### Q_M contract proposed for an explicit decision

**Research proposal, not implemented or approved.** Keep T and A's existing meanings. Materialise a separate native-reader facet with three operation keys: `(owner, decode-sequence)`, `(owner, annotation-method, name)` and `(owner, enum-variable, name)`. Use the existing canonical codec and ContentTree, not another tree implementation. A recipe is an ordered sequence with counted nested values/sites; named lookup answers distinguish absence from a selected declaration and include only the symbol/type properties consumed by the supported operation. The decoder sequence includes private/filtered annotation and default sites in native processing order. The enum query searches native VAR declarations, including private/non-enum fields; the method query follows native zero-argument selection, not Java accessibility lookup. Missing class/completion failures need exact answer modelling or continued explicit rejection.

This facet is bound to the actual binary origin, independently of k and a: the new tests prove that equal k/a cannot select its answer. Its exact root is an acceleration/storage coordinate. The observed keyed answers enter ACI; the facet root or whole jar identity does not. Different origins with equal k are resolved through the actual ordered compiler binding, using the existing first-origin indexing approach, and a winner change compares the consumed native-reader answers. This requires a versioned binding/codec amendment, not pretending the current leaf key uniquely identifies reader state.

Cold binary extraction must materialise these projections once while class bytes are available. Capture records actual native operations, not all potential questions inferred from loaded classes. CI stores the keyed observations. Reverse X gains the corresponding operation/name namespace; facet Diff and provider changes select those consumers before validation. Frozen processor bytes discharge only their own payload; lookup answers about another origin remain separate observations. Pool reuse must retain/revalidate the same observations and diagnostic policy rather than lose completion-time warnings. Module header validation and arbitrary processor observations remain separate obligations.

Cost obligation: cold work is bounded by the class metadata/declarations already parsed plus emitted projection bytes; bodies/Code are excluded. Storage is proportional to projected sites and distinct named lookup answers, with immutable sharing via ContentTree. Runtime validation/candidate work must depend on changed consumed operation keys and current fan-out, with explicit ordered-sequence bytes and tree work counted. A scalar/payload or member-property omission requires a native negative control before it can be excluded. No measured implementation cost or complete minimality theorem is claimed yet.

The decision sought is whether to introduce this distinct operation-addressed native-reader facet and version its binding/proof/candidate codecs. It is **not** approval to change T/A semantics, adopt a new tree, widen ACI to jar/route hashes, or remove the guard before all native positive/negative and supported-reuse gates pass. The brief's §4.2 says to retain the abstract Q_M name until its representation is agreed; the confirmed private-answer counterexample makes this a representation decision rather than a routine T-only collector fix.

**Research proposal / decision boundary.** The brief's K and P refinements are recorded analytically in [the existing feasibility comparison](pr62-locality-feasibility.md). No parser prototype, packing amendment, global radix, second production tree, format change or expected-locality acceptance is inferred. Correctness and indexed validation continue independently.
