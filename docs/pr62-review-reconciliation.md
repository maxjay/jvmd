#### Smallest proposed versioned amendment

**Research proposal for a decision, not installed bytes.** Keep T/N/O/A/EA, S|k/ST and the existing resolution sums unchanged. Reuse ContentTree/ContentList nodes and Ann/Codec; no second tree implementation or dependency scheduler. Introduce one logical reader image and one extension of the existing query grammar:

1. **Local image.** Extend the existing class-parse result/ClassMemo value to carry the reader view alongside ClassFacts. Parse ClassModel once before API filtering. For every selected class (including classes with no T facts), materialise its presence/support status, ordered symbolic recipe and native named-declaration inputs. Exclude Code/executable bodies for these operations. Preserve the native member-entry policy and declaration order; do not materialise an unbounded absent-name map. A recipe uses existing ordered ContentList elements containing a site/attribute envelope and existing Ann encodings. Its list hash is the bounded recipe answer/reference; CI never copies recipe bytes. Do not key list entries by absolute ordinals in a map. Prolly/CAP locality limits still apply.
2. **Exact origin binding.** Each input origin carries an independent reader-image root, even when k/a are equal or claimLeaf(k) loses. Rooted LOCAL RT/own-view selections copy these roots into immutable BV, rather than looking them up through today's P alias. To keep MACHINE-only images reachable too, add a reader-origin catalog ContentTree root to the committed MACHINE ROOT envelope (selected immutable origin content→image root); retain the existing M and its resolution sum unchanged. P and Indexed results carry the image coordinate for binding, not for ACI. Image contents live in existing N nodes; a catalog/format change, not a family of per-concept blob prefixes. Publish/sync the image even on reused resolution leaves. Both equal-k origins, filtered classes and close/reopen need direct tests.
3. **Question grammar.** Extend the existing typed question sum type with M, rather than overload T's kind values. Proposed M key: `u8 M || u8 universe || utf16 requestingModule || utf16 owner || u8 operation || utf16 argument`. The universe distinguishes ordinary task classpath, frozen processor input and platform; own/sibling/stub/real is a selected representation coordinate in that universe, not automatically another logical question or a physical path in every key. Names use existing lossless Codec.utf16; T/N/D encodings retain their existing grammar. Module-aware queries that are not supported remain non-reusable, rather than treating different lookup universes as equal. Additional operation arguments must be explicitly versioned, not silently concatenated.
4. **Outcome grammar.** A typed outcome distinguishes present(local answer identity), absent-member-with-present-owner, owner-absent, completion-failed(detail plus its actual dependency witnesses), and unsupported. Absence is an explicit proof outcome, not an absent CI entry. A failure is never the zero sum. Phase-one support may keep failed/unmodelled cases rejected while recording native evidence; this is not completed supported acceptance. Successful generic/default/type answers carry separately captured cross-input questions. Raw declaration recipes do not masquerade as environment-dependent decoded results. Diagnostic provenance is a separate consumed presentation input only if the actual retained diagnostic fields depend on it; physical paths must neither be added wholesale nor erased from native messages.
5. **ACI/CI/X.** Key-bind each observed outcome identity with the existing digest; feed the same observations into ACI, the CI query tree and current reverse X. CI gains an independent reader-binding root. Binding equality must compare it before an equal-own-k/route shortcut. The root is an acceleration coordinate, excluded from ACI. Transition preparation diffs changed origin/image branches once, resolves winners in the actual context, derives changed answers and removes equal-answer substitutions before joining current X. Missing providers seek the shorter universe/owner prefix, reaching explicit absent-member consumers. Historical receipts resolve their own immutable images, never a current path alias. Reuse candidate deduplication and changed-unit atomic publication.
6. **Compatibility fence.** Proposed allocation, subject to the decision: MACHINE layout 5 with explicit readerProjection=1 and unchanged T/A parser 6; LOCAL 23 for rooted origin/view binding; bodies 15 and CI 2 for M observations and reader binding, automatically fencing X. The projection/adapter contract becomes a fixed compiler input, independently of the exact image locator. Cold reconstruction only. Numbers are reserved here, not applied; update authoritative Stage 1/2/3 appendices together on adoption. This preserves L as a function of k and AL as a function of a.

The catalog and origin indexes are prepared once per immutable scope/input, not per body or named query. Exact-content comparison is needed where the existing projected h omits a changed provider value. Named lookup state must support direct keyed lookup, not repeated scans of every class member. A selected native candidate can depend on signature completion: no cold shortcut may label it an environment-independent success merely because its raw descriptor is present. Adaptive query traces remain valid only while fixed inputs and all prior actual answers agree.
